# bench/ — воспроизводимый регрессионный/замерный харнесс

Скрипты запускаются **из корня проекта** интерпретатором из venv:

```
venv/Scripts/python.exe bench/<script>.py
```

Каждый сам добавляет `src/` (и, где нужно, `tests/`) в `sys.path`, конфиг берёт из
`entity_types.yaml` в корне. Генерируемые ими `*_out*.txt` / `*.docx` — не отслеживаются
(см. `.gitignore`).

## Контроль регресса детекции адреса (волна 2)

| Скрипт | Что проверяет | Эталон |
|---|---|---|
| `verify_golden.py` | Полнота/детекция/ложные на **golden-наборе** (`tests/golden_addresses.py`, 89 адресов + 16 не-адресов) + захват >3 симв. на изолированных строках | detect 89/89, full-closure 89/89, FP 0/16, over-capture 0 |
| `verify_external.py` | Обобщение на **внешнем наборе** (15 адресов вне golden: др. регионы/форматы) + демонстрация избыточного правого захвата В КОНТЕКСТЕ | detect 15/15, full 15/15; захват за адресом виден (W2-D2) |
| `verify_pipeline2.py` | Полный конвейер `detect_regex+detect_ner→merge→tokenize` на реквизитных строках; **репро утечки W2-D1** | пишет `bench/pipe_out2.txt`; «Казань/Баумана» остаются открытыми = утечка |
| `verify_bcde.py` | Эквивалентность батч-B3 ↔ по-оконный, синтаксис составных (позитивы/негативы), all-caps-инвариант | batched == ref бит-в-бит |
| `verify_compound_perf.py` | Разложение времени детекции по стадиям на синтетике 6000 сегментов | см. `WAVE2_VERIFICATION.md`, §5 |
| `verify_f.py`, `verify_f2.py` | B3 через границу таблицы/строки под all-caps (split-ИНН/ФИО) — на реальном `.docx` | утечки нет |
| `bench_detection.py` | Общий замер encrypt-детекции | — |
| `golden_run.py` | Разовый прогон golden по категориям | — |

**Golden-набор и внешний набор — оба сохранены и под контролем:**
- Golden: `tests/golden_addresses.py` + `tests/test_golden_addresses.py` (195 тестов, отслеживаются).
- Внешний набор (15 адресов): инлайн в `verify_external.py` (отслеживается здесь).

Отчёт, для которого эти скрипты — доказательная база: `docs/reports/WAVE2_VERIFICATION.md`.
