# HANDOFF — Блок 8: Ядро OOXML (`ooxml_core.py`)

## Что сделано
Реализовано ядро Компонента 2 — всё, что одинаково для `.docx`/`.xlsx`/`.pptx` и не
знает ни про один конкретный формат. Модуль умеет читать OOXML-архив в память с
защитой от zip-бомбы (`read_zip_parts`), точечно пересобирать его с сохранением
порядка записей, метода сжатия и дат (`rewrite_zip`), парсить/сериализовать
XML-части без порчи документа (`parse_xml`/`serialize_xml`) и — центральный алгоритм
компонента — заменять токены в группе текстовых узлов, включая токены, физически
разорванные между несколькими узлами (`replace_tokens_in_group`). Оформление не
трогается вообще: меняется только текстовое содержимое writable-узлов. Модуль ничего
не делает при импорте (импорт ~0.09 c, только за счёт `lxml`).

## Публичный интерфейс

Все имена импортируются одной строкой:
```python
from ooxml_core import (
    Resolver, TOKEN_RE, OoxmlError, TextUnit, RunGroup,
    replace_tokens_in_group, read_zip_parts, rewrite_zip, parse_xml, serialize_xml,
)
```

### Типы и константы
```python
Resolver = Callable[[str], str | None]
# принимает токен целиком, включая скобки: "[ORG_1]"; возвращает original_text либо
# None, если токен неизвестен сессии.

TOKEN_RE = re.compile(r"\[[A-Z_]+_\d+\]")
# TOKEN_RE совпадает с паттерном блока 6 (detokenizer.py) ПОСИМВОЛЬНО.
# При изменении формата токенов правятся ОБА места (импорт из detokenizer.py запрещён).

class OoxmlError(Exception): ...  # битый/недопустимый контейнер или zip-бомба
```

### `TextUnit` / `RunGroup`
```python
@dataclass
class TextUnit:
    node: object    # lxml-элемент текстового узла (<w:t>/<a:t>/<t>), либо None
    text: str       # текущий текст (для псевдо-разделителя — фиксированное значение "\n")
    writable: bool  # True — в узел можно писать; False — псевдо-разделитель

@dataclass
class RunGroup:
    units: list[TextUnit]  # строго в порядке следования текста в документе
```

### `replace_tokens_in_group`
```python
def replace_tokens_in_group(group: RunGroup, resolve: Resolver) -> list[str]: ...
```
Заменяет токены во всех units группы (включая разорванные между units). Мутирует
`u.text` и — для writable-units — `u.node.text`. Возвращает список НЕразрешённых
токенов в порядке появления (с возможными повторами; дедупликацию делает блок 12).
Исключений сам не бросает (кроме падений из переданного `resolve`, если тот бросит —
это ответственность вызывающего). Минимальный пример:
```python
from lxml import etree
from ooxml_core import TextUnit, RunGroup, replace_tokens_in_group
W = "{http://schemas.openxmlformats.org/wordprocessingml/2006/main}"
n1 = etree.Element(W+"t"); n1.text = "[ORG"
n2 = etree.Element(W+"t"); n2.text = "_1] прочее"
g = RunGroup([TextUnit(n1, "[ORG", True), TextUnit(n2, "_1] прочее", True)])
unresolved = replace_tokens_in_group(g, lambda tok: {"[ORG_1]": "ООО «Ромашка»"}.get(tok))
# n1.text == "ООО «Ромашка»", n2.text == " прочее", unresolved == []
```

### ZIP
```python
def read_zip_parts(src_path: str) -> dict[str, bytes]: ...
def rewrite_zip(src_path: str, dst_path: str, modified: dict[str, bytes]) -> None: ...
```
`read_zip_parts` — `{имя_части: байты}`. Исключения: `OoxmlError` (не ZIP / повреждён /
zip-бомба), `FileNotFoundError` (файла нет — **пробрасывается наверх, не оборачивается**).
`rewrite_zip` — исключений своего типа не бросает; пробрасывает I/O-ошибки, при этом
временный файл гарантированно удаляется. Пример:
```python
from ooxml_core import read_zip_parts, rewrite_zip, parse_xml, serialize_xml
parts = read_zip_parts("in.docx")                 # dict[str, bytes]
tree = parse_xml(parts["word/document.xml"])       # ... правки узлов ...
rewrite_zip("in.docx", "out.docx", {"word/document.xml": serialize_xml(tree)})
```

### XML
```python
def parse_xml(data: bytes): ...      # -> lxml ElementTree
def serialize_xml(tree) -> bytes: ...
```
`parse_xml` может бросить `lxml.etree.XMLSyntaxError` (модуль `lxml.etree`), если байты —
не well-formed XML (адаптеры блоков 9–11 подают сюда только реальные части OOXML, где
это не ожидается). `serialize_xml` исключений не бросает.

## Формат данных на выходе
- `replace_tokens_in_group` → `list[str]`, например `["[ORG_1]", "[PERSON_2]", "[ORG_1]"]`
  (порядок появления, повторы возможны) или `[]`.
- `read_zip_parts` → `dict[str, bytes]`, например
  `{"[Content_Types].xml": b"<?xml ...", "word/document.xml": b"<?xml ...", ...}`.
- `serialize_xml` → `bytes`, начинается ровно с
  `b'<?xml version="1.0" encoding="UTF-8" standalone="yes"?>\r\n'`.

## Инварианты выходных данных
- **`replace_tokens_in_group`:** возвращаемый список — **в порядке первого появления
  токена в склеенном тексте группы, с повторами** (не дедуплицирован, не отсортирован).
- Значение целиком пишется в тот unit, где токен **начинался**; символы токена в
  последующих units удаляются, сами узлы/runs **не удаляются** (могут остаться с пустым
  текстом — это нормально).
- Оформление (`<w:rPr>`, `<a:rPr>`, атрибут `s`, `xml/styles.xml`) не читается и не
  меняется. Единственный атрибут, который метод может **добавить**, —
  `xml:space="preserve"` на узле, чей итоговый текст начинается/заканчивается пробелом;
  уже стоящий атрибут никогда не снимается.
- В резолвнутом значении `\r` и `\n` заменяются на пробел перед вставкой.
- **`read_zip_parts`:** ключи словаря — имена записей архива; порядок ключей = порядок
  записей в архиве (Python 3.7+ dict сохраняет порядок вставки).
- **`rewrite_zip`:** в `dst_path` — те же записи, в том же порядке, с тем же
  `compress_type` и `date_time`, что в `src_path`; изменены только байты частей из
  `modified`; ни одна запись не добавлена и не удалена. Публикация через `os.replace`
  (атомарно), временный файл — в директории `dst_path`.
- **`serialize_xml`:** XML-декларация всегда присутствует, `standalone="yes"`, префиксы
  пространств имён не переобъявляются.

## Что блок ожидает на входе (предусловия)
- `RunGroup.units` идут строго в порядке следования текста в документе; между
  текстовыми узлами, физически разорванными нетекстовым элементом (`<w:br/>`, `<w:tab/>`,
  `<a:br/>`), адаптер обязан вставить псевдо-unit `TextUnit(node=None, text="\n",
  writable=False)`. Ядро учитывает его текст при склейке, но никогда в него не пишет —
  это защита от ложного склеивания двух фрагментов в псевдо-токен (`\n` ∉ `TOKEN_RE`).
- Для `writable=True` unit `node` — валидный lxml-элемент, в `.text` которого можно
  писать. Ядро не проверяет корректность узла; если `writable=True`, а `node is None`,
  такой unit тихо пропускается при записи.
- `resolve` не бросает исключений в штатном режиме; если бросит — исключение уйдёт
  наверх, группа останется частично обработанной (ядро не откатывает уже записанное).
- `modified` в `rewrite_zip` содержит только имена, реально существующие в `src_path`;
  «лишние» имена в `modified` тихо игнорируются (в архив не попадают, т.к. перебор идёт
  по записям исходного архива).

## Зависимости и окружение
- Python: `Python 3.11.9` (проверено `python --version`).
- Внешняя зависимость — только `lxml` (проверено: `lxml 6.0.2`; `lxml` уже присутствует

- **Запрещённые здесь библиотеки не используются:** `python-docx`, `openpyxl`,

## Соглашения о путях и файлах времени выполнения
Блок не владеет постоянными путями. `read_zip_parts`/`rewrite_zip` работают с путями,
которые передал вызывающий. `rewrite_zip` создаёт временный файл `*.tmp` в директории
`dst_path` (через `tempfile.mkstemp(dir=...)`) и удаляет/переименовывает его сам;
никаких других файлов не создаёт. Архив никогда не распаковывается на диск — только в
память.

## Отклонения от спецификации
Отклонений нет. Уточнения реализации (в рамках спеки):
- XML-декларация формируется вручную (`b'<?xml ... standalone="yes"?>\r\n'`), потому что
  `lxml` печатает её в одинарных кавычках, а спека требует двойные и явный `standalone`.
- `parse_xml` возвращает результат `etree.parse(BytesIO(...))` (полноценный ElementTree),
  а не `etree.fromstring`, — чтобы сохранить комментарии/PI вокруг корневого элемента.
- В `rewrite_zip` для каждой записи создаётся свежий `ZipInfo` с копированием
  `compress_type`, `date_time`, `external_attr`, `internal_attr`, `create_system`,
  `create_version`, `extract_version`, но **без** переноса `flag_bits` — чтобы бит
  data-descriptor исходной записи не рассинхронизировался с тем, как `writestr` пишет
  запись. Требование спеки (сохранить `compress_type` и `date_time`) выполнено.

## Известные ограничения / TODO
**Ответ на обязательный вопрос компонента — что мой блок гарантированно не портит и
чего он в принципе не видит:**
- **Гарантированно не портит** (потому что не касается): любые узлы и атрибуты
  оформления (`<w:rPr>`, `<a:rPr>`, `<w:pPr>`, `<a:pPr>`, атрибут `s` у `<c>`,
  `xl/styles.xml`, темы, изображения, `[Content_Types].xml`), структуру абзацев/runs
  (узлы не удаляются, только меняется `.text`), любые части архива, не переданные в
  `modified` (переносятся с тем же именем/сжатием/датой), порядок и число записей архива.
- **В принципе не видит** (это не его уровень абстракции): какие части архива и какие
  узлы считать текстом — это решают адаптеры (блоки 9–11); искажённые LLM токены
  (`[org_1]`, `ORG_1`, `[ORG 1]`) — не распознаёт (тот же `TOKEN_RE`, что в блоке 6).
- **Осознанные ограничения ядра:**
  - `\r`/`\n` в значении заменяются на пробел (в OOXML перенос строки внутри текстового
    узла ведёт себя непредсказуемо; согласовано с `build_plain_text` блока 4).
  - Zip-slip неприменим: архив читается только в память, на диск не распаковывается —
    отдельной защиты от имён вида `../../` не требуется (зафиксировано по требованию спеки).
  - Защита от zip-бомбы: суммарный **распакованный** размер > 200 МБ **или** число
    записей > 5000 → `OoxmlError` до чтения содержимого (пороги — `_MAX_TOTAL_UNCOMPRESSED`
    и `_MAX_ENTRIES`).

## Данные для тестов
Ниже — реально проверенные сценарии (входы → выходы), включая граничные.

1. **Токен, разорванный между runs (ключевой сценарий).**
   units: `"Договор с "`, `"[ORG"`, `"_1] на сумму"`; `resolve("[ORG_1]") -> "ООО «Ромашка»"`.
   → тексты units: `"Договор с "`, `"ООО «Ромашка»"`, `" на сумму"`; `unresolved == []`;
   у третьего узла выставлен `xml:space="preserve"` (ведущий пробел), у первого — нет.

2. **Неизвестный токен (граничный).**
   Та же группа, `resolve -> None`.
   → тексты units **не изменились ни в одном символе**; `unresolved == ["[ORG_1]"]`.

3. **Псевдо-разделитель блокирует склейку (граничный).**
   units: `"[PHONE"`, псевдо-`"\n"` (`writable=False`), `"_1]"`; `resolve` знает `"[PHONE_1]"`.
   → замена **не происходит** (разрыв реальным `\n`), тексты не изменились, `unresolved == []`.

4. **Два токена в одном unit.** `"x[A_1]y[B_2]z"`, `[A_1]->"AA"`, `[B_2]->"BB"`
   → `"xAAyBBz"` (правки от конца к началу не сбивают оффсеты).

5. **Экранирование.** `[D_1] -> "A & B < C"` → `.text == "A & B < C"`, в сериализации
   `A &amp; B &lt; C` (экранирует lxml; руками не экранируем).

6. **ZIP round-trip без правок (граничный).** `rewrite_zip(src, dst, {})` на реальном
   `wert.docx` (34 записи) → набор и порядок записей совпадают, `compress_type`+`date_time`
   сохранены, распакованное содержимое идентично, `zipfile.testzip()` возвращает `None`.

7. **Не-ZIP файл.** `read_zip_parts(<файл с мусором>)` → `OoxmlError`. Несуществующий путь
   → `FileNotFoundError` (не обёрнут).
