## Дефект: валидный OOXML-контейнер без единой целевой части не отклоняется

**Файл теста:** `tests/component2/test_e_malformed_input.py::test_valid_zip_without_any_target_part_raises_ooxml_error`
**Статус:** тест красный (намеренно, код не правился).

**Что не так.** `ooxml_core.read_zip_parts` проверяет только "это вообще
ZIP" и защиту от zip-бомбы (число записей / суммарный распакованный размер).
Она не проверяет, что архив содержит хотя бы одну из частей, которые адаптер
формата ожидает увидеть (`word/document.xml`, `xl/sharedStrings.xml` /
`xl/worksheets/sheet*.xml`, `ppt/slides/slide*.xml`). Адаптеры (`docx_rewriter`,
`pptx_rewriter`, `xlsx_rewriter`) при отсутствии таких частей просто не находят
целевых имён (`names` — пустой список), ничего не переписывают и вызывают
`rewrite_zip` с пустым `modified`, что производит **побайтовую копию входа**
как «успешный» результат: `unresolved == []`, исключения нет, `dst_path`
создан.

**Минимальный воспроизводящий пример:**
```python
import zipfile
from docx_rewriter import rewrite

with zipfile.ZipFile("not_really_docx.docx", "w") as zf:
    zf.writestr("unrelated/part.txt", b"hello world")

unresolved = rewrite("not_really_docx.docx", "out.docx", lambda t: None)
# unresolved == [] , out.docx создан — никакой ошибки, хотя это вообще не .docx
```

Тот же эффект — с `.xlsx` без `xl/sharedStrings.xml`/`xl/worksheets/sheet*.xml`
и с `.pptx` без `ppt/slides/slide*.xml`: любой валидный ZIP с расширением
`.docx/.xlsx/.pptx`, но без содержимого этого формата, "успешно" проходит
через `detokenize_file`.

**Чем это грозит пользователю.** Компонент принимает **чужой, неконтролируемый
файл от внешней LLM/агента** (см. постановку задачи) — именно тот случай,
когда входной файл может оказаться битым, не тем форматом или подставным.
Сейчас пользователь получит код возврата `0`/успешный вызов `detokenize_file`
и файл `..._restored.docx`, который выглядит как "всё раскрыто" (`unresolved
== []`), хотя на самом деле файл вообще не был обработан как OOXML —
компонент просто скопировал непонятные байты. Отличить "в файле правда не
было токенов" от "это не настоящий .docx" пользователь не может, и попадёт
на это только когда откроет файл вручную и увидит, что это не документ вовсе
(или получит от коллеги файл без единого исправления и решит, что токены и
правда не найдены).

**Предлагаемое (не реализованное) исправление**, вне рамок этого набора
тестов: `read_zip_parts` или сами адаптеры должны бросать `OoxmlError`, если
после фильтрации по маске формата не нашлось ни одной целевой части архива.
