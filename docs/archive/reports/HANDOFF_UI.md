# HANDOFF — десктоп-интерфейс SHIFRATOR (пилот)

Дата: 2026-07-20. Ветка `main`. Новая папка `app/`; `src/` детекции, `measure_lib`,
`tests/corpus`, `MANIFEST.sha256` **не тронуты** (интерфейс — надстройка).

## Что сделано

Функциональный локальный десктоп-интерфейс поверх реального CLI: полный цикл
**шифрация → проверка → восстановление** на настоящей системе, без моков. Центр —
ЭКРАН ПРОВЕРКИ (юрист проверяет за системой, которая не гарантирует полноту).

Файлы:
- `app/server.py` — HTTP-сервер на стандартной библиотеке (`http.server`,
  `ThreadingHTTPServer`), слушает только `127.0.0.1:8765`. Эндпоинты:
  `GET /` (страница), `POST /api/encrypt` (сырые байты файла + заголовки
  `X-Filename`/`X-Allow-Lossy`), `POST /api/decrypt` (JSON `{session_id, text}`).
  Переводит типизированные ошибки конвейера в человеческий текст (без трейсбека),
  прячет внутренний временный путь за именем файла пользователя.
- `app/core.py` — тонкая обёртка. Дёргает реальный конвейер из `src/` в порядке
  `shifrator.py::cmd_encrypt` (regex ПЕРВЫМИ → `detect_ner` → `merge_compound_entities`
  → `tokenize` → `save_session` → запись `{sid}.txt`) и дополнительно возвращает то,
  что CLI выбрасывает: исходный/обезличенный HTML с подсветкой (через реальный
  `tokenizer._assemble` — выравнивание по настоящим оффсетам гарантировано), список
  замен (дедуп по токену, как в `session_store`), непрочитанные зоны. Политика зон
  идентична CLI: strict по умолчанию → `EncryptRefused`; `--allow-lossy` → работа +
  sidecar `{sid}.unread.json` с сырым текстом зон (локально, в LLM не идёт).
- `app/index.html` — единственная страница (vanilla HTML/CSS/JS, без сборки, без
  внешних ресурсов), 3 экрана.
- `app/start.bat` — запуск двойным кликом через `venv`.
- `app/README.md` — инструкция для себя и пилотного юриста.

## Стек и почему

Локальный веб (stdlib `http.server` + одна HTML-страница), а НЕ PySide6/Tkinter и
НЕ FastAPI. Причины: (1) экран проверки требует подсветки замен и всплывающих
подсказок при наведении — в HTML/CSS тривиально, в Tkinter мучительно; (2) ноль
новых зависимостей — в `venv` нет ни FastAPI, ни Qt, а `pip install` Qt-колёс на
машине пилота — риск; на стандартной библиотеке запуск гарантирован; (3) тот же
интерпретатор, прямой импорт конвейера, без subprocess; (4) только `127.0.0.1` —
приватность ПДн. Обоснование отказа от альтернатив — там же.

## Как проверялось (реальный прогон, не моки)

- `app/core.py` на копиях корпусных `.docx` в scratchpad (корпус не трогал):
  чистый round-trip **точный** (`restored == build_plain_text`), зоны корректно
  ведут к отказу, `--allow-lossy` пишет sidecar, strip(HTML) == plain/anon_text
  (подсветка выровнена посимвольно).
- Эндпоинты `server.py` по-настоящему через HTTP-клиент: refuse на зонах, lossy-ok,
  decrypt round-trip, битый `.docx` / неверный ID / неподдерживаемое расширение —
  все дают человеческий текст, не трейсбек.
- Полный цикл в реальном браузере (in-app Browser): загрузка `.txt` с ПДн →
  экран проверки активен, 12 замен подсвечены и сгруппированы по типу, исходная
  панель содержит ПДн, обезличенная — только токены (`[PERSON_1]`, `[INN_1]`…),
  подсказка при наведении верна; восстановление вернуло **точный** оригинал;
  предупреждение о непрочитанных зонах рендерится с таблицей и осознанным выбором.

## Приёмка ТЗ — статус

Все пункты выполнены: реальный `.docx` (шифрация → список замен + подсветка →
скачивание), документ с колонтитулом (явное предупреждение + выбор, не проглочено),
round-trip к точному оригиналу, человеческие ошибки без трейсбека, запуск одной
командой/кликом, ничего в сеть (только `127.0.0.1`).

## Границы и на будущее

- Подсветка честно показывает и известные огрехи самой системы (напр. ADDRESS
  over-capture `«, выдан ОВД…»`, находки 0c-C/D в `STATE.md`) — это не дефект
  интерфейса, а именно то, ради чего нужен экран проверки.
- Тестов интерфейса в `tests/` не добавлял (надстройка вне регресс-гейта). Если
  захотим CI на `app/` — стоит завести отдельный `tests/app/` с HTTP-клиентом,
  чтобы не смешивать с замерным гейтом `src/`.
- Только `.docx`/`.txt` на входе (как и CLI encrypt). PDF/веб — вне этой задачи.
