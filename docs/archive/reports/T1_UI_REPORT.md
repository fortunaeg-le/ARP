`type_policy.resolve/load_settings/enabled_types`) **не тронут ни в одной

## ШАГ 0. Установленные факты

### 0а. Как сейчас читается файл настроек

| | |
|---|---|
| путь | `~/.shifrator/settings.json` — `type_policy.settings_path()`, `src/type_policy.py:151` |
| читает | `type_policy.load_settings()`, `src/type_policy.py:157` |
| когда, в UI | `app/core.current_policy()`, `app/core.py:72` — **при каждой шифрации**, не на импорте (перезапуск ради смены набора не нужен); вызывается из `core.run_encrypt`, `app/core.py:366` |
| когда, в CLI | `type_policy.enabled_types(config_path)` внутри `shifrator.cmd_encrypt`, `shifrator.py:133` |
| замер/гейт | **не читают вовсе** — `tests/corpus/run_measurement.py` зовёт токенизацию с явной константой `type_policy.MAXIMUM` |
| если файла нет | исключения нет: `load_settings` ловит `OSError`/`ValueError` и возвращает `{"profile": DEFAULT_PROFILE, "types": {}}`, то есть набор «только персональные данные». То же самое — на битом JSON, не-словаре, неизвестном имени набора; неизвестный тип в `types` молча игнорируется |

Направление ошибки безопасное: умолчание — самый узкий набор, опечатка в файле
приводит к тому, что замаскировано будет НЕ МЕНЬШЕ обещанного умолчанием.

### 0б. Экран настроек в интерфейсе

**Не было — заведён с нуля.** До этапа интерфейс имел четыре экрана
(`app/index.html`: `scr-enc` / `scr-ver` / `scr-res` / `scr-ana`, навигация —
`nav` на `index.html:166`, переключатель — `show()`, `index.html:368`) и ни
одного API-маршрута про настройки (`Handler.do_GET`/`do_POST`,
`app/server.py:197,237`). Файл настроек правился только руками.

### 0в. Где показывается результат обезличивания

Экран **2 · Проверка**, секция `scr-ver` (`app/index.html:210`), рендер —
`renderVerify(d)` (`index.html:474`): ID сессии, счётчик «спрятано N значений ·
M замен», два текста рядом, легенда типов, список замен по типам. Данные —
результат `core.run_encrypt` (`app/core.py:402`), он же кладётся в `CUR` на
клиенте. Строка «каким набором получен результат» добавлена сюда.

### 0г. Признак версии установки

**Отдельного признака версии на диске нет.** Есть `core.BUILD_MARK`
(`app/core.py:68`, строка `u1b-rebuild-20260725`) — но он живёт в КОДЕ, а не в
данных пользователя, и по нему нельзя отличить «эта сборка уже запускалась» от
«запускается впервые»: он одинаков при каждом запуске одной сборки.

Заводить файл версии ради этого этапа не требуется, и это отдельное решение:
**вопрос «обновление или первая установка» задаётся ровно один раз в жизни
установки**, и ответом на него служит сам факт отсутствия файла настроек.
Как только решение принято, файл существует — и второй раз вопрос не возникает
(ветка «файл есть» закрывает его навсегда). Признак версии понадобился бы для
других задач (миграции формата настроек), в этой он избыточен.

## ШАГ 1. Обновление против первой установки

`type_policy.ensure_settings()` (`src/type_policy.py`), вызывается из
`app/core.current_policy` и из `shifrator.cmd_encrypt` — CLI и интерфейс обязаны
видеть один файл в одном состоянии.

| состояние диска | что делаем | почему |
|---|---|---|
| файл настроек **есть** | ничего | выбор пользователя уважается; битый файл тоже НЕ перезаписывается — это чужие данные |
| файла нет, **есть следы прошлой работы** | пишем `maximum` | это обновление: до T1 маскировалось всё, и молча сузить набор человеку, который уже работает, значит изменить результат его работы без спроса |
| файла нет, следов нет | пишем `personal` | первая установка, умолчание продукта |

### Как именно определяется «следы прошлой работы»

`type_policy.has_previous_work()` — **закрытый** список маркеров в
`~/.shifrator` (`_WORK_TRACES`), достаточно любого одного:

1. `sessions/` — непустой каталог хранилища сессий;
2. `sessions/key.bin` — ключ шифрования сессий, создаётся ПЕРВОЙ шифрацией;
3. `markup/` — непустой каталог ручной разметки (этап U3).

Два решения внутри, каждое проверено тестом:

* **список закрытый, а не «в каталоге вообще что-то лежит».** Рядом лежит
  `launcher.lock`, который создаёт САМ запуск интерфейса
  (`app/launcher.py:37`) — по нему первая установка выглядела бы обновлением
  (`test_launcher_lock_alone_is_not_a_trace_of_previous_work`);
* **каталог-след считается следом, только если НЕПУСТ**: пустую папку могла
  создать неудавшаяся попытка, обосновывать решение «это обновление» она не
  должна (`test_empty_sessions_dir_is_not_a_trace`).

Запись атомарная (`tmp` + `os.replace`): оборванная запись оставила бы юриста с
битым JSON, то есть молча сброшенным набором. Ошибка записи (нет прав) не
фатальна — программа продолжит работать на умолчаниях `load_settings`, а не
откажется обезличивать документ.

**Живое подтверждение на машине владельца.** До этапа в `~/.shifrator` лежали
`sessions/`, `markup/` и `launcher.lock`, файла настроек не было. Первый же
запуск нового кода записал:

```json
{"profile": "maximum", "types": {}}
```

то есть распознал обновление и сохранил прежнее поведение — ровно как решено.

## ШАГ 2. Экран

Вкладка **«5 · Что маскировать»** (`app/index.html`, секция `scr-set`), маршруты
`GET /api/settings` и `POST /api/settings` (`app/server.py`), данные —
`core.settings_view()` / `core.save_settings()`.

Как выглядит сверху вниз:

1. Заголовок «Что маскировать» и пояснение: *«Поиск всегда идёт по всем типам —
   набор решает только, что заменять на маску. Настройка применяется к
   следующему обезличиванию; уже готовые документы не меняются.»*
2. **Четыре набора** — радиокнопки в рамках, выбранная подсвечена. У каждого
   название и одна строка человеческим языком, без имён типов из кода:
   * **Только персональные данные** — ФИО, адреса, телефоны, почта, паспорта,
     СНИЛС, даты рождения;
   * **Персональные данные и реквизиты** — всё перечисленное выше и, кроме
     того, названия организаций, ИНН, ОГРН, КПП, БИК, банковские счета;
   * **Всё, включая деньги** — всё перечисленное выше и, кроме того, денежные
     суммы;
   * **Максимум (все типы)** — все типы данных, которые программа умеет
     находить, без исключений.
3. **Отдельные типы** — 14 галочек с русскими названиями (ФИО, Организация,
   Адрес, ИНН, ОГРН/ОГРНИП, КПП, Банковский счёт, БИК, Паспорт, СНИЛС, Дата
   рождения, Телефон, E-mail, Сумма). Галочки показывают фактический состав
   выбранного набора; снятая или поставленная галочка переопределяет набор.
4. Кнопка **«Сохранить»**, строка состояния и путь к файлу настроек.

Решения, которые стоит назвать явно:

* **Состав набора считает СЕРВЕР.** Браузер не знает, какие типы входят в
  набор: и наборы, и типы, и состояние галочек приходят из `src/type_policy.py`.
  Иначе экран разошёлся бы с механизмом при появлении нового типа — тот же класс
  рассинхрона, против которого заведён `src/pipeline.py`.
* **Смена набора сразу применяет его и перерисовывает галочки** (а прежние
  точечные исключения сбрасывает): пользователь выбрал набор, а не «набор плюс
  мои прошлые исключения». Результат виден глазами до нажатия «Сохранить».
* **Перекрытия, совпадающие с набором, в файл не пишутся** — это не выбор, а
  шум, который вдобавок залип бы при следующей смене набора
  (`test_screen_does_not_store_overrides_that_repeat_the_set`).
* **`DATE` на экран не выводится**: его детектор выключен в
  `entity_types.yaml` (`enabled: false`), масок не будет ни при какой галочке —
  предлагать её значило бы обещать невыполнимое. Из состава политики тип при
  этом не выкинут (там он значим для набора «Максимум»).
* **Второго места хранения нет.** Экран пишет тот же
  `~/.shifrator/settings.json` в том же формате
  (`test_screen_saves_into_the_same_file_the_mechanism_reads`).

## ШАГ 3. Чем обезличено — на экране результата

`core.policy_summary()` кладёт в результат шифрации слепок
**момента шифрации** (тот же, что уходит в sidecar сессии), и `renderVerify`
показывает его над легендой типов:

* полный набор —
  «Обезличено набором **«Максимум (все типы)»** — маскировались все типы данных,
  которые программа умеет находить.»
* не полный — в рамке-предупреждении:
  «**Обезличено набором «Только персональные данные» — это не все типы данных.**
  Намеренно НЕ маскировались: Организация, ИНН, Сумма. Если они есть в
  документе, они остались открытым текстом — это ваша настройка, а не пропуск
  программы. Изменить — вкладка «5 · Что маскировать».»

`DATE` из перечня «осталось намеренно» исключён по той же причине, что и с
экрана настроек.

## ПРИЁМКА

### 1. Первая установка — умолчание «только персональные данные»

Живой сервер, изолированный домашний каталог, `GET /api/settings`:

```
profile = "personal"
включено: ФИО, Адрес, Паспорт, СНИЛС, Дата рождения, Телефон, E-mail
выключено: Организация, ИНН, ОГРН/ОГРНИП, КПП, Банковский счёт, БИК, Сумма
```

Файл создан программой: `{"profile": "personal", "types": {}}`.
Тест — `test_fresh_install_gets_the_personal_default`.

### 2. Обновление — умолчание «Максимум»

Показано дважды: на машине владельца (шаг 1 выше) и тестом на каждом из трёх
маркеров по отдельности — `test_upgrade_keeps_the_previous_behaviour_maximum`
(`sessions/key.bin`, файл сессии `*.enc`, файл разметки).

### 3. Существующий файл не перезаписывается

`test_existing_settings_file_is_never_overwritten` — файл с
`{"profile": "with_money", "types": {"EMAIL": false}}` остаётся байт в байт даже
при наличии следов работы. Битый файл тоже не перезаписывается
(`test_broken_settings_file_is_left_alone_and_does_not_crash`).

### 4. Выбор на экране меняет реальный результат — ЧИСЛА

Документ корпуса `tests/corpus/docs/agency_0002.docx`, реальный путь UI-шифрации
(`core.run_encrypt`), настройка задаётся через экран (`core.save_settings`):

| набор на экране | масок всего | по типам |
|---|---:|---|
| Только персональные данные | **12** | ADDRESS 4, EMAIL 2, PERSON 2, PHONE 4 |
| То же + галочка «ИНН» | **14** | + INN 2 |
| Персональные данные и реквизиты | **28** | + BANK_ACCOUNT 4, BIK 2, KPP 1, OGRN 2, ORG 5 |
| Всё, включая деньги | **30** | + SUM 2 |
| Максимум | **30** | то же |
| Максимум минус галочка «Телефон» | **26** | всё, кроме PHONE 4 |

Читается так: поставили галочку «ИНН» — масок стало на 2 больше и значение
`7707083893` исчезло из обезличенного текста; сняли «Телефон» — исчезли ровно
4 маски PHONE, остальные 26 не изменились. Строка «чем обезличено» на первых
трёх строках говорит «это не все типы данных» и перечисляет оставшееся, на
«Всё, включая деньги» и «Максимум» — «маскировались все типы».
Тест — `test_turning_a_type_on_and_off_changes_the_masks`.

### 5. Урезанный файл настроек НЕ меняет цифры гейта — ЧИСЛА

Два уровня.

**а) Побайтное сравнение пути замера.** `test_measurement_ignores_the_user_settings_file`:
одна и та же детекция, `tokenize(..., enabled_types=type_policy.MAXIMUM)` до и
после записи файла `{"profile":"personal","types":{"EMAIL":false,"PHONE":false}}`
(проверено, что `enabled_types()` при этом реально урезан). Анонимизированный
текст и карта масок (тип, токен, исходное значение) — **равны**.

**б) Полный гейт при урезанном файле настроек.** `tests/corpus/gate.py`,
`~/.shifrator/settings.json` = `{"profile":"personal","types":{"EMAIL":false}}`:

Полный лог — `experiments/stage_t1_ui_gate.log`. Результат:

```
ГЕЙТ ЗЕЛЁНЫЙ: регрессов не найдено по всем четырём линиям
(а precision / б leak_v2 / в masking A / г masking B) + креши/FP/MANIFEST/долг.
```

Все охраняемые числа побайтно равны baseline (в логе — `X -> X` в каждой
строке), при том что файл настроек урезан до `personal` без `EMAIL`:

| число | baseline | этот прогон |
|---|---:|---:|
| recall TOTAL | 82.0% | 82.0% |
| leak_v2 ≥6 TOTAL | 19.3% | 19.3% |
| precision PER / ORG / ADDRESS | 99.96 / 99.78 / 99.93 | 99.96 / 99.78 / 99.93 |
| FP на негативах | 15 | 15 |
| masking A / B / C | 100.00 / 86.95 / 95.37 | 100.00 / 86.95 / 95.37 |
| известный долг ADDRESS | 63 | 63 |

Ни одна цифра не сдвинулась — гейт мерит работу программы, а не настройку
пользователя. Файл настроек после прогона возвращён в исходное состояние.

### 6. Битые настройки не роняют программу

Проверено на парсере, на экране
(`test_settings_file_with_unknown_type_does_not_crash_the_screen`: неизвестный
набор → умолчание, неизвестный тип не попадает на экран) и на живом HTTP —
`POST /api/settings` с телом «не json» отвечает
`{"status": "error", "message": "Неверный запрос: ..."}`, сервер продолжает
работать.
