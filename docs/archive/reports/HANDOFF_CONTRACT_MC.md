## 1. Требование, которое оцифровано

Модель эксплуатации: после автоматической шифрации документ проверяет **человек**. Отсюда
асимметрия ошибок:

| ошибка | тяжесть | почему |
|---|---|---|
| **пропуск** (сущность не замаскирована) | терпимо | человек поймает на проверке |
| **кривая маскировка** (замаскировано неверно) | **недопустимо** | человек ищет, не осталось ли ЛИШНЕГО; он НЕ проверяет, правильно ли спрятано уже спрятанное — кривая маскировка проходит проверку насквозь и уходит в результат |

Значит, всё, что система замаскировала **автоматически**, обязано быть замаскировано
**корректно**. Три уровня (согласованы с владельцем продукта):

- **A. ROUND-TRIP — жёстко.** `decrypt` возвращает замаскированное значение байт-в-байт.
- **B. ГРАНИЦЫ — жёстко.** Эталонный спан закрыт масками **целиком**, не наполовину.
- **C. ТИП — мягко.** Маска своего типа (СНИЛС не прячется под KPP). Фиксируем, но в
  красное не роняем.

**Знаменатель — маски системы, а не gold.** Это ключевое отличие от recall/leak: те отвечают
на «сколько поймали», masking_correctness — на «из пойманного, сколько спрятано корректно».
Перепутать знаменатель = молча превратить метрику в recall (пришпилено тестом
`TestRatesDenominator`).

## 3. ДОКАЗАТЕЛЬСТВО про round-trip на .docx (главный результат замера)

В FINDINGS числилось «117 .docx с пробельными расхождениями round-trip» и открытым
вопросом: попадают ли расхождения **внутрь** замаскированных значений. Замерено, не
предположено:

- документов с `roundtrip_ok=False`: **162** (не 117 — цифра в FINDINGS устарела), **все**
  `.docx`;
- из них `ws_only`: **162/162**; `len_mismatch`: **0**;
- масок, внутри которых расхождение: **477 из 17725** (в 162 документах).

**То есть ходовое предположение «расхождения только ВНЕ масок» — ЛОЖНО.** Расхождения
попадают именно внутрь замаскированных значений.

**И при этом A цел — 100%.** Причина расхождения: `tokenizer._render_table` заменяет `\n`
внутри ячейки таблицы на пробел **при сборке plain-текста**, а `detokenize` возвращает
значение с исходным `\n`. То есть восстановленное значение совпадает с **оригиналом
документа** и расходится с **лоссовой plain-сборкой**. Это артефакт текстового канала, а не
порча данных. Замена длину не меняет, поэтому координаты `plain` и `restored` совпадают
символ в символ — что и позволило проверить каждую маску поштучно.

Отсюда — **A считается двумя числами**: `a_ok` (значение вернулось ровно; жёсткое требование
продукта, по нему гейт) и `a_channel_ok` (совпал ли участок с plain; справочно). Слить их в
одно число нельзя ни в одну сторону: считать артефакт нарушением A — подгонка метрики под
канал, игнорировать молча — потеря факта. Обе половины пришпилены тестом
`test_contract_A_channel_diffs_land_inside_masks_but_value_is_intact`.

## 4. Что появилось в коде (только прибор, `src/` не тронут)

**`tests/corpus/measure_lib.py`** — блок `masking_correctness`:
- `plain_segment_offsets(doc)` — смещения сегментов внутри plain-сборки; вызывающий **обязан**
  сверить результат с `tokenizer.build_plain_text` (в `run_measurement` стоит `assert`):
  разъезд реализаций сделал бы координаты A враньём, и метрика обязана умереть громко;
- `mc_check_a(...)` → `{a_ok, a_channel_ok, reason}`, reason ∈ `ok | channel_ws_only |
  value_corrupted | unaligned`. `unaligned` (длины разошлись) считается нарушением
  **консервативно** — тот же инвариант «нет статуса неприменимо», что введён этапом 0b-fix;
- `mc_check_bc(mask, golds, all_masks)` → `{scored, b_ok, c_ok, gold_type, mask_type}`.
  B считается по **объединению** масок, накрывающих эталон (значение, закрытое двумя
  соседними масками, спрятано полностью — не брак). Маска, не легшая ни на одну эталонную
  сущность, — ложное срабатывание: `scored=False`, в знаменатель B/C **не идёт** (иначе рост
  FP автоматически ронял бы корректность);
- `mc_aggregate` / `mc_rates`; `aggregate_results` отдаёт блок `masking_correctness`.

**`tests/corpus/run_measurement.py`** — в запись документа добавлено поле `masks`: по одной
записи на КАЖДУЮ маску системы (`gtype/token/a_ok/a_channel_ok/a_reason/scored/b_ok/c_ok/
gold_type`). Маска смотрится в двух системах координат: `plain` (для A) и PT-1 (для B/C,
где размечен gold).

**`tests/corpus/gate.py`** — **условие 5**: A% и B% по агрегату не упали относительно
baseline, допуск **0** (корректность только растёт). C печатается, но гейт не роняет.
Блок печатается рядом с recall/leak. Если в baseline нет поля `masks` (снят до этой
метрики) — гейт **краснеет с требованием пересобрать baseline**, а не молчит: иначе условие 5
было бы «зелёным» просто потому, что его не с чем сопоставить.

**`tests/corpus/results_baseline.json`** — пересобран этим же кодом системы, содержит `masks`.

## 5. Защита от «всегда-зелёной метрики» (та же ловушка, что была с утечкой)

`tests/test_masking_correctness.py` — **19 passed, 2 xfailed**. У каждого уровня есть **пара**:

| уровень | положительное зеркало | отрицательное зеркало |
|---|---|---|
| A | чистый ИНН round-trip'ится → OK | (юнит) значение вернулось другим → `value_corrupted`; длины разошлись → `unaligned`; **(сквозное, реальный конвейер)** документ с литералом `[INN_1]` внутри текста ломает detokenize → метрика показывает нарушение A |
| B | эталон закрыт целиком → OK; закрыт двумя соседними масками → OK; маска **шире** эталона → OK (PASSPORT-случай, это НЕ нарушение B) | половина под маской → нарушение; дыра между двумя масками → нарушение; **(сквозное)** эталон шире маски → нарушение |
| C | тип совпал → OK | (юнит) SNILS под KPP → нарушение при целых границах; **(сквозное, замороженный корпус `agency_0003`)** реальный СНИЛС под чужим типом → метрика видит нарушение C |

Плюс `TestRatesDenominator` — пришпиливает знаменатели (A по всем маскам, B/C по легшим на
эталон), чтобы метрику нельзя было незаметно превратить в recall.

**Проверка гейта искусственной порчей** (сценарий из приёмки, выполнен): в копии baseline
портится ровно **одна** маска из 17725 —
- `a_ok=False` → `100.00% -> 99.99%`, гейт **красный**;
- `b_ok=False` → `77.81% -> 77.79%`, гейт **красный**;
- `c_ok=False` → регрессов **0** (мягкий уровень, как и задумано);
- неиспорченный прогон против себя же → регрессов 0.

## 8. Что это меняет для следующих этапов

1. У каждого этапа теперь есть **вторая половина отчётности**. Раньше этап отчитывался
   «recall вырос, leak упал». Теперь он обязан показать ещё и «A/B не упали». Этап, который
   начнёт маскировать криво ради recall (расширит спаны наугад, склеит соседние сущности),
   **покраснеет** — этого раньше не ловил никто.
2. **B=77.8% — это цифра, а не ощущение.** 2158 масок из 9723 закрывают эталон не целиком.
   Худший тип — PER (62%), и это прямая мишень этапа 2b.
3. **A=100% — доказанный, а не предполагаемый факт**, включая 162 .docx с расхождениями
   round-trip. Вопрос из FINDINGS закрыт (и цифра 117 в нём устарела — верно 162).
4. Осторожно с **C по ORG (36%)**: это в основном ФИО, поглощённые маской ORG (`PER -> ORG`,
   447 случаев). По B/A такие маски корректны, значение спрятано — поэтому C и оставлен
   мягким. Не превращать его в жёсткий, не разобравшись, где здесь дефект детекции, а где
   законная склейка «ИП + ФИО» (см. `docs/DECISIONS.md`).
