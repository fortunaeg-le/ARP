## Что сделано

1. **Двухпроходный механизм распространён на PER** (та же машина, что ORG). Новый
   `PerAnchorDetector` в `src/anchor_registry.py` подключён к тому же `AnchorEngine`
   рядом с `OrgAnchorDetector`. Natasha-PER в конфиге **выключена** (`entity_types.yaml`:
   `PERSON` → `method: anchor_registry`), как Natasha-ORG на этапе A. ФИО теперь даёт
   ТОЛЬКО структура.
   - **Якорь ФИО** структурно, по грамматическим пометам pymorphy `Surn/Name/Patr`
     (порог правдоподобия счёта `_NAMEPART_MIN_SCORE=0.01` отсекает мусорные разборы —
     предлог «по» имел разбор-фамилию «По»/Эдгар По со счётом 8.9e-05). НИКАКИХ
     словарей фамилий/имён.
   - **Само-якорь**: фамилия + имя/отчество ЛИБО фамилия + инициалы (99.7% ФИО корпуса).
     Голая фамилия анкорится ТОЛЬКО при внешнем маркере: «гражданин/гражданка/гр.»,
     должность, «в лице …, действующего…», ИП, соседний ИНН-12/СНИЛС физлица.
     Безъякорная одиночная фамилия сознательно пропускается (класс Aprime-1 для PER).
   - **Полный спан ФИО** (закрывает PER-B): `_fio_run` собирает связный прогон
     фамилия+имя+отчество+инициалы в ОДИН спан, включая косвенный падеж
     («Морозовой Анне Николаевне» = один спан, не два). Не опирается на границы Natasha.
   - **Реестр по лемме ФАМИЛИИ**, проход 2 распространяет по падежам (guard).
   - **Вторичный ключ (имя, отчество)** от уверенного полного ФИО — накрывает
     осиротевшее «Имя Отчество» в СОСЕДНЕМ сегменте (cross-segment split, вне области
     `Entity.spans`). Структурно, внутри документа.

2. **Инвариант «одна лемма = один тип» — арбитраж в реестре, симметрично ORG↔PER**
   (`AnchorEngine.run`, двухфазный pass-1: собрать все якоря → отсортировать по силе
   доказательств (ORG вперёд PER при равенстве) → записать в реестр → эмитить спаны
   ПОБЕДИВШЕГО типа). «Восход», взятый ORG-якорем, не перетипируется в PER;
   зарегистрированная фамилия не станет ORG. ORG и PER эмитятся одним движком, взаимно
   не поглощаются (`emitted_src` в ИСХОДНЫХ координатах — общий язык для двух видов).

3. **Guard коллизий PER**: строчная фамилия-омоним («мороз» в середине) не метится;
   заглавная в начале предложения без второго признака не метится; **адресный
   тип-маркер слева** («ул. Пушкина», «ш. Гагарина») → топоним-однофамилец, не человек
   (`_PER_ADDR_TYPE_LEFT_RE`).

4. **Раздельные поисковые виды ORG/PER** (`per_search_view` vs `anchor_search_view`):
   ключ ORG однотокенный («Ромашка») — `\n` внутри слова ВЫРЕЗАЕТСЯ (склеивает форму);
   ключ PER многотокенный («Беляев Олег Олегович») — `\n` на границе слов заменяется
   ПРОБЕЛОМ (иначе «БеляевОлег» — нераспознаваемый токен). Мутация `t_linebreak` ставит
   `\n` в случайную позицию; для ФИО это обычно граница слов.

5. **A-2 погашен**: «Стороны: ИП Иванов И.И. и ООО «Ромашка»» → ДВЕ ORG. PER анкорит
   «Иванов И.И.» по ИП-маркеру; `merge_compound_entities` склеивает ИП-форму,
   ВПЛОТНУЮ примыкающую к ФИО, БЕЗ опоры на appos-направление (парсер в сочинительной
   конструкции цепляет ФИО к корню предложения, не к «ИП»). xfail снят.

6. **A-3 погашен**: «Глава КФХ Петров» → «Петров» = PERSON, НЕ единый ORG-блоб.
   Роль-слово слева от org-формы (`_ROLE_BEFORE_FORM_RE`) → ORG не грабит имя за формой;
   PER анкорит по роль-маркеру. Голая «КФХ» без имени организацией не считается. xfail снят.

7. **Барьер PER↔ORG↔ADDRESS**: `detect_ner` принимает `per_entities`; структурные PER-
   и ORG-спаны — безусловный барьер расширения адреса И источник «занятых» имён для
   отсева yargy-ложняков (`_filter_suspect_yargy`, раньше опирался на Natasha-PER/ORG,
   теперь пустой — заменён структурными спанами; иначе yargy-ложняк на «Иванов»
   сшивался с адресом и тянул метку «адрес:» в токен).

8. **КОНСОЛИДАЦИЯ ТОЧЕК ВХОДА** (`src/pipeline.py::run_detection`): единственная копия
   порядка шагов (regex → структурный ORG+PER → адрес-NER с барьерами → арбитраж →
   составные). `shifrator.py` (CLI), `app/core.py` (UI), `tests/corpus/run_measurement.py`
   (замер) — все ТРОЕ зовут её, ни у кого нет своей копии. Устраняет класс UI-рассинхрона
   (трёхчасовой инцидент этапа A′). `BUILD_MARK="stage-b-per"`.

**masking_correctness** (знам. — маски системы):
- **A (round-trip) = 100.00% → 100.00%** — инвариант выдержан, ноль порчи значения
  (value-corrupting round-trip = ∅ и в A′, и в B; остаточные ws-only несовпадения — это
  предсуществующий Aprime-3 `\n`→' ' канал, не утечка).
- **B (границы) = 81.87% → 89.75%** (+7.9pp) — прямой эффект косвенного падежа одним спаном.
- C (тип, информационно) = 92.95% → 91.94% (−1.0pp, гейт не роняет).

**Три метрики гейта:**
1. **ORG не деградирует**: recall ↑ (93.9→94.2%), exact неизменен. leak_v2 ORG
   +1.6pp (leak≥8 3.9→6.7%) — это **MASK-SHIFT, не регрессия детекции**: 8 сущностей
   «Петров Консалтинг» (`cession_0004`, `loan_0001` + мутации) — класс **Aprime-1 ORG**
   (имя фирмы грамматически = фамилия+слово, введено «именуемое в дальнейшем» БЕЗ
   org-формы/кавычек/ИНН → структурного якоря нет). Раньше Natasha-PER СЛУЧАЙНО метила
   их PERSON (маскировало → утечки не было); с выключением Natasha-PER они вернулись в
   своё истинное неякорное состояние. −6 leak (ООО «Иванов»-мутации, наоборот, починены).
   Ровно параллель MASK-SHIFT этапа A. Механизм PER утечки НЕ вносит.
2. **Корректность не падает**: A=100%, B ↑. (C −1pp — мягкий, печатается.)
3. **Ложные PER не растут**: FP-на-негативах PER **11 → 1** (общий FP 1293→1283).
   Остаточные ложные PER (6, лишь 1 на объявленном негативе), поимённо:
   - `labor_0006__m2718_linebreak` «Полев\nая», `labor_0010__m2718_invisible` «Баум ана»,
     `services_0012__m2718_case` «ГАГАРИНА», `works_0008__m1337_combo` «Ш.  ПУШКИНA» —
     улицы-однофамильцы под АДВЕРСАРИАЛЬНОЙ мутацией (перенос/невидимый/регистр рвут
     адресный тип-маркер слева, `_addr_type_left` его не видит); cross=ADDRESS.
   - `lease_0010__m1337_linebreak` «УСЛОВ\nИЯ», `services_0014__m2718_linebreak`
     «московскому време» (часовой пояс) — мусорные разборы под мутацией.
   Все 6 — под мутациями; на чистом тексте ложных PER 0.

**Что ещё рвётся у PER (поимённо, среди пропусков/недобора):**
