# HANDOFF — Этап 1: обнаружение непрочитанных зон .docx и fail-closed

**Статус:** 1a (сканер) и 1b (политика отказа) сделаны в одной сессии.
**Что НЕ делалось:** зоны по-прежнему НЕ читаются — это этап 6. Этап 1 учит систему
честно ОБНАРУЖИВАТЬ зоны и громко ОТКАЗЫВАТЬСЯ, а не молча терять текст.

---

## 1. Зачем (напоминание)

`src/extractor.py` читает только верхний уровень тела `word/document.xml`
(`document.element.body.iterchildren()` → `w:p` и `w:tbl`). Не читаются:
колонтитулы, сноски, концевые сноски, примечания, надписи (`w:txbxContent`),
таблицы, вложенные в `w:tc`. Замер этапа 2 показал recall по
`in_header/in_footer/in_footnote/in_textbox/nested_table` **ровно 0%**.

До этого этапа содержимое зон молча выбрасывалось: пользователь получал анонимный
текст без куска договора и не знал об этом. Анонимайзер, который молча теряет
текст, хуже того, который отказывается работать.

### Сканер (1a)

`Zone = {kind, part, char_count, text_preview, text}`; `kind ∈ {header, footer,
footnote, endnote, textbox, nested_table, comment}`. Поле `text` (сырой текст
целиком) — сверх ТЗ: без него sidecar не смог бы показать, что именно выброшено.

Работает через **zip + lxml, не через python-docx** — принципиально: python-docx и
есть источник слепоты (`paragraph.text` не спускается в `txbxContent`, `Document()`
не открывает `header*`). Проверять полноту чтения инструментом, чья неполнота
проверяется, — заведомо ложноотрицательный результат.

Три решения, которые стоит знать:

1. **Надписи ищутся по тегу `w:txbxContent`, а не по родителю.** У надписи два
   кодирования — VML (`w:pict/v:shape/v:textbox`) и DrawingML
   (`mc:AlternateContent/mc:Choice/w:drawing/wps:txbx`, с VML-дублем в
   `mc:Fallback`). Оба кладут внутрь один и тот же `w:txbxContent`, поэтому поиск
   по тегу ловит оба разом и не пропустит третье, если Word его заведёт. Плата:
   `AlternateContent` с обоими вариантами даст две зоны на одну надпись —
   осознанный ложноположительный вместо риска пропуска. (В корпусе — только VML.)
2. **Вложенная таблица — это `w:tbl`, у которого есть предок `w:tc`.** Не
   `tc.iter(tbl)`: последний дал бы дубли на таблице, вложенной на два уровня.
3. **Части, кроме `document.xml`, объявляются зоной ЦЕЛИКОМ** (одна зона на часть,
   для сносок — одна на запись). Внутри `document.xml` зоной объявляются только
   непрочитанные подузлы — иначе отказывал бы каждый .docx.

Отсечки: служебные сноски-разделители (`w:id` = `-1`/`0`) не зона; зона значима
только при наличии непробельного символа в `w:t` (пустой `header1.xml` python-docx
кладёт почти в каждый документ — отказ на нём был бы отказом на всём).

Битая XML-часть **не проглатывается**: становится зоной с пометкой «часть не
разобралась». Тихо вернуть «зон нет» на битой части — ровно тот молчаливый провал,
против которого написан модуль.

### Политика (1b)

- **По умолчанию strict:** `exit code 2`, таблица «тип зоны / часть / символов /
  начало текста» на **stdout**, подсказка про `--allow-lossy`. Сессия и `{sid}.txt`
  НЕ создаются (проверка порядка: политика применяется после `extract`, до
  `save_session`).
- **`--allow-lossy` / `strict_zones: false`:** громкое предупреждение с таблицей в
  stderr + sidecar `{sid}.unread.json` рядом с сессией, содержащий **сырой текст**
  зон. Флаг перекрывает конфиг; умолчание при нечитаемом конфиге — strict
  (fail-closed).
- `.txt` политики не касается — он читается целиком.

**Отметка сессии как lossy — это сам факт наличия sidecar'а**, а не поле в
`{sid}.enc`. Причина: формат зашифрованной сессии есть контракт блока 5
(`tests/component2/test_f_session_contract.py`), расширять его ради пометки нельзя.
Отдельный файл рядом с `{sid}.txt` даёт то же самое, не трогая чужой контракт.

Sidecar содержит ПДн открытым текстом — осознанно: смысл файла в том, чтобы
пользователь увидел выброшенное. Наружу (в LLM) уходит только `{sid}.txt`; sidecar
остаётся локально, как и `{sid}.enc`.

## 4. Замер и сопоставимость с baseline

`run_measurement.py` гоняет систему в lossy-режиме (`ALLOW_LOSSY = True`). Это не
косметика, а условие существования замера: в strict 135 из 162 docx отказались бы,
и recall/leak обнулились бы на пустом месте.

**Цифры по телу документа не изменились и не могли измениться**: зоны не читались и
ДО этапа 1 (recall по ним ровно 0%), а политика отказа не трогает детекцию. Гейт это
подтвердил: **все 13 типов — байт-в-байт baseline → текущий**, ни одного регресса и ни
одного «улучшения» (последнее было бы таким же тревожным сигналом — значит, этап задел
детекцию, чего он делать не должен):

```
TOTAL*  10932 |  recall 56.3%->56.3% | leak_v2>=6 48.0%->48.0% | leak_v2>=8 43.0%->43.0% | FP 1968->1968
Гейт ЗЕЛЁНЫЙ: регрессов не найдено.
MANIFEST.sha256 (до прогона): 656 файлов — OK / (после прогона): OK
```

Исходы документа теперь **все три настоящие**:
- `processed` — обработан (штатный lossy-прогон);
- `refused` — отклонён политикой (возникает при `allow_lossy=False`);
- `crashed` — упал с необработанным исключением.

У каждого документа в results появилось поле `refused_zones` —
`[{kind, part, char_count}]`. Сырой текст зон там НЕ хранится (в отличие от
sidecar'а): для метрики хватает `kind/part/char_count`, а класть ПДн в файл, который
может уехать в git, незачем.

Фактический прогон этого этапа — дамп гейта `tests/corpus/results_gate_current.json`
(gate.py зовёт тот же `RM.run_all`, что и `main()`; отдельный `results_stage1.json`
не плодил). Он же подтверждает цифры §5:

```
outcomes:              {'processed': 324}     # lossy — отказов нет, как и задумано
docs with refused_zones: 135
total zones:             150   {header:30, footer:30, footnote:30, textbox:30, nested_table:30}
```

По конвенции репозитория в git коммитится только `results_baseline.json` — остальные
`results_*.json` остаются локальными.

## 6. Изменение контракта (сообщается явно)

`src/extractor.py` печатал предупреждение в stderr на вложенную таблицу
(`Предупреждение: вложенная таблица в ячейке t0_r0_c0 не извлечена (MVP)`). ЗАДАНИЕ
§1b требовало это заменить: «Никаких молчаливых warning в stderr (текущее поведение
для вложенных таблиц именно такое — заменить)».

Warning удалён. Существовавший тест
`tests/test_extractor.py::TestExtractDocxNestedTableWarning::test_nested_table_prints_warning_with_cell_coordinates`
проверял ровно это поведение и был **переписан** под новый контракт
(`TestExtractDocxNestedTable::test_nested_table_is_not_extracted_and_extract_stays_silent`):
теперь он проверяет, что текст вложенной таблицы не извлекается **и** что
`extract()` при этом молчит.

**Это не «подгонка теста под правку», а запрошенная заданием смена контракта** —
фиксирую явно, потому что граница «тест упал — это находка» тут задета осознанно.
Обоснование: warning ничего не останавливал и терялся среди прочего stderr, т.е. был
ровно той тихой потерей, которую этап 1 закрывает. За громкость теперь отвечает
политика отказа, а не печать из библиотечного слоя; `extract()` — библиотечная
функция, её дело извлечь, что умеет, а не решать за вызывающего.
