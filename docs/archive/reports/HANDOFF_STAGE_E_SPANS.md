# HANDOFF — Этап E: Entity.spans + единый id + канон при восстановлении

**Ветка:** `stage-e-spans` (от `25fd7bc` = main + принятый C′; `main` без C′ не
двигался, расхождения нет). **Дата:** 2026-07-23. Смена базовой модели данных;
ГЛАВНЫЙ ИНВАРИАНТ — структурная целостность восстановления — выдержан: **1a = 0
провалов на всех 324 документах корпуса и на реальном договоре**.

## 1. Модель spans (часть 1)

`Entity` получил три опциональных поля (`src/models.py`), все с дефолтом None —
обратная совместимость на уровне кода, ни один детектор не переписан:

- `spans: list[(start,end)] | None` — диапазоны ЗНАЧЕНИЯ в исходных координатах,
  отсортированы, не пересекаются. `[start,end)` остаётся ОБОЛОЧКОЙ (hull) от
  начала первого куска до конца последнего; разделители между кусками входят в
  hull и в `original_text` (= `segment.text[start:end]`) байт-в-байт, но не в
  spans. None == однодиапазонная (частный случай `[(start,end)]`, хелпер
  `entity_spans`).
- **Маскируется всегда hull одним токеном** — решение в пользу целостности:
  восстановление подставляет `original_text` целиком, разделители внутри
  (перенос, скобка, пробел) сохраняются побайтно без всякой логики склейки.
- `group_key`, `canonical` — см. части 2–3.

## 2. Где мультиспан ПРИМЕНЁН (часть 1b) — `src/multispan.py`

Сборщик работает на том же `detection_view`, что и regex-детекторы; его сущности
вливаются в regex-слой в `pipeline.run_detection` (те же барьеры/пересечения).

- **(а) PHONE в произвольной группировке**: цепочки цифро-подобных групп
  (цифры + несведённые омоглифы `бОЗЧІ`) через разделители ` ()-—+` (без `\n`),
  принимаются ТОЛЬКО если суммарно 10–11 эффективных цифр с ведущей 7/8 и групп
  ≥2. Ловит «+7 (Ч99) 286-20-б2», «84б 82б85 1Ч», «8(383)22 1338б» — жёсткая
  структура 3-3-2-2 штатного паттерна такие разбиения не матчит.
- **(б) BANK_ACCOUNT, рваный `\n`**: цепочка с `\n` в разрыве, ровно 20 цифр,
  ОБЯЗАТЕЛЕН якорь счёта слева (правило этапа 4 сохранено). **BIRTHDATE, рваная
  `\n`**: дата под якорем рождения (те же якоря yaml), `\n` допускён внутри
  значения.
- НЕ в этой сессии (осознанно, «сузить риск»): границы ячеек docx (B3-пары),
  116 рваных ADDRESS долга, cross-segment ORG. Модель готова, сборка — следующая
  сессия.

**Анти-склейка (зеркало −, `tests/test_stage_e_spans.py`)**: цепочка
принимается только при длине ОДНОГО значения — два счёта в столбик дают 40
цифр → отвергается целиком (под-окна запрещены: 10-цифровое «окно» внутри
чужого 20-значного числа не выдёргивается); телефон не цепляется через `\n` →
два номера в столбик не сливаются. Оба кейса — явные тесты.

## 3. Единый id (часть 2)

Токен переиспользуется по `group_key` (реестр кореференции), а не по
поверхностной форме: «Меркурий/Меркурия/Меркурием» → один `[ORG_1]`.
- ORG: `group_key` = ключ записи реестра (лемма ядра) — реестр уже кореферирует
  падежи.
- PER: **PersonBook** (`src/anchor_registry.py`) — реестр PER ключуется леммой
  фамилии, чего для id НЕДОСТАТОЧНО (тёзки!). Персона определяется совместимостью
  имени/отчества/инициалов; «Иванов Иван Петрович» и «Иванов Сергей Максимович»
  — разные id (тест-зеркало); неатрибутируемая голая фамилия при двух тёзках
  получает нейтральную «фамильную» персону (канон — только фамилия: ложная
  атрибуция хуже неатрибуции).
- ADDRESS/regex-типы: без реестра — нумерация по (тип, текст), как раньше.
- B3-половины токен не делят (свой original_text — свой токен), как раньше.

## 4. Канон при восстановлении + формат сессии v2 (часть 3)

**Формат сессии v2** (`session_store.save_session`, payload `"format": 2`).
Запись — одна на токен:
- v1-поля `token/entity_type/original_text/segment_id` СОХРАНЕНЫ (original_text
  = форма первого вхождения) — старые читатели (file_detokenizer) работают без
  изменений;
- `canonical` — каноническая форма из реестра (ORG — юридическая форма лучшего
  якоря: «ООО «Меркурий»»; PER — ФИО в именительном, pymorphy inflect с
  сохранением рода: «Новиковой Ольги Егоровны» → «Новикова Ольга Егоровна»);
  null у типов без реестра;
- `occurrences` — ВСЕ вхождения токена в порядке документа:
  `{segment_id, start, end, spans, surface}`. **Пишем всё, читаем пока только
  канон** — формы каждого вхождения записаны ради будущих склонения по контексту
  и режима точного восстановления; сессии без них остались бы неполноценными
  навсегда.

**Восстановление** (`detokenizer.detokenize`):
- `mode="canonical"` (умолчание; CLI decrypt и UI автоматически): токен →
  канон, fallback original_text (regex-типы, v1-сессии). Сценарий владельца —
  текст возвращается из LLM переписанным, исходная форма вхождения неприменима.
- `mode="exact"`: n-е вхождение токена → surface n-го замаскированного
  вхождения. Используется структурной приёмкой (харнесс `run_measurement` —
  masking A обязана быть 100%) и валиден только на неизменённом тексте.
- **Обратная совместимость**: v1-сессия (без format/canonical/occurrences)
  читается обоими режимами → original_text (тест
  `test_v1_session_backward_compatible`). Ломать ничего не пришлось.
- `file_detokenizer` (decrypt-file) НЕ тронут: он строит mapping по
  original_text (= первая форма). Известное следствие: для ORG/PER с
  унифицированным токеном в файл подставится форма первого вхождения, не канон
  — задокументировано, приведение к канону файлового пути = отдельное решение.

## 7. Находки/остаток

- **PHONE-сборщик и 10-значные не-телефоны**: цепочка ≥2 групп с 10 цифрами и
  ведущей 7/8 может быть ИНН-10/паспортной парой без якоря. На корпусе это дало
  НОЛЬ новых fp_neg (650=650) и снизило утечку PASSPORT/SNILS (маскирование —
  безопасное направление); PHONE cross 11→29 — рост cross-type диагностики,
  не утечка. Наблюдать на гейте D.
- Канон PER построен pymorphy-инфлексией с сохранением рода; на экзотических
  фамилиях возможна неточная нормальная форма — канон предъявляемый, не
  байтовый; exact-формы всех вхождений в сессии (восстановимо всегда).
- `file_detokenizer` подставляет форму первого вхождения (см. §4) — приведение
  файлового пути к канону не делалось.
- Двухсегментные разрывы (B3-пары, cross-segment ORG, 116 ADDRESS долга) —
  следующая сессия на этой модели.
