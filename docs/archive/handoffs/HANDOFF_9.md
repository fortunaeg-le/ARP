## Что сделано
Реализован адаптер `.docx` для Компонента 2 — единственная публичная функция
`rewrite(src_path, dst_path, resolve)`. Модуль сам не ищет и не заменяет токены:
он определяет, какие части архива открыть (`word/document.xml`, `word/header*.xml`,
`word/footer*.xml`, `word/footnotes.xml`, `word/endnotes.xml`), строит по одной
`RunGroup` на каждый `<w:p>` (units — все `<w:t>` абзаца в порядке следования,
`<w:br>`/`<w:tab>` — псевдо-разделители), и вызывает `ooxml_core.replace_tokens_in_group`
для каждой группы. Вся замена, включая токены, разорванные между `<w:r>`, и стиль
вставленного значения — целиком в ядре (блок 8). Проверено эмпирически на синтетическом
`.docx` (форматированный run, разорванный токен, `<w:br>`, таблица, нумерованный список,
колонтитулы, неизвестный токен) и на реальном `test_document.docx` из `test_run/`.

## Публичный интерфейс
```python
from docx_rewriter import rewrite

def rewrite(src_path: str, dst_path: str, resolve: Resolver) -> list[str]: ...
```
`Resolver` — тот же тип, что в блоке 8 (`Callable[[str], str | None]`), отдельно не
переопределяется, импортируется из `ooxml_core`.

Минимальный пример вызова:
```python
from docx_rewriter import rewrite

mapping = {"[PERSON_1]": "Иванов Иван Иванович", "[ORG_1]": "ООО «Ромашка»"}
unresolved = rewrite("ответ.docx", "ответ_restored.docx", lambda tok: mapping.get(tok))
# ответ_restored.docx создан на диске; unresolved -> [] (если все токены известны)
```

Исключения:
- `OoxmlError` (`ooxml_core`) — если `src_path` не ZIP/повреждён/zip-бомба. Пробрасывается
  из `read_zip_parts` без изменений.
- `FileNotFoundError` — если `src_path` не существует. Пробрасывается из `read_zip_parts`
  без изменений (стандартное исключение Python, не оборачивается).
- `lxml.etree.XMLSyntaxError` — если одна из целевых частей архива не well-formed XML
  (не ожидается для настоящих OOXML-файлов, но не перехватывается и не маскируется).
- Исключения из переданного `resolve`, если он их бросает, — не перехватываются, часть
  документа может остаться частично обработанной (тот же контракт, что у
  `replace_tokens_in_group` в блоке 8).

## Формат данных на выходе
`rewrite(...)` возвращает `list[str]`, например `["[ORG_99]"]` или `[]`. Побочный эффект —
файл `dst_path` создан на диске (тот же набор записей архива, что в `src_path`, тот же
порядок, `compress_type`/`date_time` сохранены для не тронутых блоком 9 частей).

## Инварианты выходных данных
- unresolved — **в порядке первого появления в документе**, с возможными повторами
  (если один и тот же неизвестный токен встретился несколько раз — он в списке несколько
  раз; дедупликацию делает блок 12). Порядок обхода частей: `word/document.xml`, затем
  `word/header*.xml` (по имени файла), `word/footer*.xml` (по имени файла), затем
  `word/footnotes.xml`, затем `word/endnotes.xml`. Внутри части — порядок `<w:p>` в дереве
  (document order), внутри абзаца — порядок `<w:t>`/`<w:br>`/`<w:tab>` в поддереве абзаца.
- Части архива, не входящие в маску (стили, темы, изображения, `[Content_Types].xml`,
  `docProps/*`, `customXml/*`, `numbering.xml` и т.п.) — байт-в-байт идентичны исходным
  (проверено: `word/styles.xml` и `word/theme/theme1.xml` совпадают побайтово до и после
  `rewrite`).
- Части, входящие в маску, но отсутствующие в конкретном архиве (нет колонтитулов,
  сносок) — просто пропускаются, не создаются с нуля.
- Оформление (`<w:rPr>`, `<w:pPr>`, любые атрибуты кроме текста `<w:t>` и, при
  необходимости, `xml:space`) не читается и не изменяется — гарантия ядра (блок 8),
  адаптер сам оформление не трогает вовсе.
- Удалённый текст рецензирования (`<w:del>`/`<w:delText>`) никогда не попадает в units —
  адаптер ищет только тег `<w:t>`, а не `<w:delText>`, поэтому исключение достигается самой
  формой обхода, без отдельной проверки предков.
- Токен не может «перепрыгнуть» границу абзаца: `RunGroup` строится на уровне `<w:p>`,
  соседние абзацы никогда не склеиваются в одну группу.

## Что блок ожидает на входе (предусловия)
- `src_path` — путь к файлу, который **является** OOXML-контейнером (проверяет и об этом
  сигнализирует `OoxmlError` ядро, блок 9 сам не проверяет расширение — этим занимается
  блок 12).
- Внутри целевых частей архива структура — валидный WordprocessingML: `<w:t>` содержит
  текст в `.text` (может быть `None`, тогда трактуется как `""`), `<w:p>` не вложены друг
  в друга. Если структура нарушена нестандартным генератором — поведение не определено
  (не тестировалось за пределами того, что производит Word/python-docx).
- `resolve` — чистая функция без побочных эффектов, вызывается многократно и в порядке
  появления токенов слева направо, отдельно для каждой группы.

Блок не владеет постоянными путями. Пишет ровно один файл — `dst_path`, через

## Отклонения от спецификации
Отклонений нет. Уточнение реализации: части, попавшие в маску, при `rewrite` всегда
проходят через `parse_xml`/`serialize_xml` (реконструируются lxml), даже если в них не
найдено ни одного токена — спецификация гарантирует байт-в-байт сохранность только для
частей, **не попавших в маску** (см. блок 9, «части архива, не попавшие в маску... —
переносятся... нетронутыми»); для попавших в маску это не требуется и не проверялось как
отдельный инвариант.

## Известные ограничения / TODO
**Ответ на обязательный вопрос компонента:**
- **Гарантированно не портит:** любые узлы/атрибуты оформления во всех обработанных
  частях (`<w:rPr>`, `<w:pPr>`, нумерация, нумерованные списки, нумерация полей); части
  архива вне маски (стили, темы, шрифты, изображения, `docProps`, `customXml`,
  `numbering.xml`, `[Content_Types].xml`) — байт-в-байт; структуру таблиц (`<w:tbl>`) и
  вложенность обёрток (`<w:hyperlink>`, `<w:smartTag>`, `<w:ins>`) — узлы не удаляются и не
  перемещаются, меняется только `.text` у `<w:t>`; удалённый текст рецензирования
  (`<w:delText>`) — не видит и не трогает вовсе.
- **В принципе не видит:** содержимое `mc:AlternateContent` (запасные представления
  графики/canvas) отдельно не разбирается — если внутри такого блока есть параллельные
  `<w:p>` с `<w:t>`, они попадут в общий обход `root.iter(_W_P)` наравне со всеми, это не
  тестировалось специально, но не исключено архитектурой (то же дерево, тот же обход);
  искажённые LLM токены (`[org_1]`, `ORG_1`, `[ORG 1]`) — не распознаёт, это `TOKEN_RE`
  ядра (то же ограничение, что у блока 6).
- **Осознанное ограничение:** мастера/шаблоны, встроенные объекты OLE, диаграммы внутри
  `.docx` не анализируются на текст — это вне описанных частей архива и не предполагалось
  спецификацией блока 9.

## Данные для тестов
Реально проверенные сценарии (`venv/Scripts/python.exe`, синтетический `.docx`, собранный
для проверки, плюс реальный `test_run/test_document.docx`):

1. **Форматированный run.** `[PERSON_1]` внутри run с `bold=True`, `size=Pt(26)`,
   `color=FF0000`; соседние runs без форматирования. После `rewrite` с
   `resolve("[PERSON_1]") -> "Иванов Иван Иванович"` — текст run'а стал «Иванов Иван
   Иванович», `bold`/`size`/`color` не изменились; соседние runs не изменили оформления.
2. **Токен, разорванный на два `<w:r>`.** Runs `"Контакт: "`, `"[PHONE"`, `"_1] сегодня."`
   → после `rewrite` (`resolve("[PHONE_1]") -> "+7 495 123-45-67"`) абзац:
   `"Контакт: +7 495 123-45-67 сегодня."`, значение целиком в run'е, где токен начинался.
3. **`<w:br>` как псевдо-разделитель (граничный).** Абзац: run `"[TAB_1]"` + `<w:br/>` +
   run `"после переноса"`. После `rewrite` (`resolve("[TAB_1]") -> "ЗНАЧЕНИЕ"`) — текст
   первого run'а стал `"ЗНАЧЕНИЕ\n"` (перевод строки сохранился физически как `<w:br/>`,
   в тексте python-docx он читается как `"\n"`), второй run не изменился; ложного
   склеивания токена через перенос не произошло.
4. **Токен в колонтитуле.** `header.paragraphs[0].text == "Шапка: [ORG_1]"` → после
   `rewrite` — `"Шапка: ООО «Ромашка»"`. Футер без токенов не изменился.
5. **Токен в таблице.** Ячейка `"Организация: [ORG_1]"`, соседняя `"ИНН: [INN_1]"` → обе
   раскрыты корректно, стиль ячейки не проверялся отдельно (за него отвечает не блок 9;
   узлы ячейки не удалялись).
6. **Неизвестный токен (граничный).** `"Неизвестный: [ORG_99] здесь."`, `resolve` не знает
   `[ORG_99]` → текст не изменился ни в одном символе, `unresolved == ["[ORG_99]"]`.
7. **Файл без колонтитулов/сносок (граничный).** `test_run/test_document.docx` (только
   `word/document.xml`, без header/footer/footnotes/endnotes) → `rewrite` отрабатывает без
   ошибок, отсутствующие части маски просто пропущены, набор записей архива на выходе
   совпадает с исходным (`namelist()` равны).
8. **Округлостность архива.** Для всех прогонов: `zipfile.testzip()` выходного файла ->
   `None`; `namelist()` входа и выхода совпадают; `compress_type`/`date_time` не тронутых
   блоком 9 частей (`word/styles.xml`, `word/theme/theme1.xml`) — байт-в-байт идентичны.
