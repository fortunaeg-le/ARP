## Что сделано
Реализован адаптер `.xlsx` для Компонента 2 — единственная публичная функция
`rewrite(src_path, dst_path, resolve)`. Модуль сам не ищет и не заменяет токены: он
определяет, какие части архива открыть и какие узлы считать текстом, и вызывает
`ooxml_core.replace_tokens_in_group` для каждой группы. Учтено главное отличие xlsx от
docx/pptx: строковое значение ячейки хранится не в самой ячейке, а в общей таблице строк
`xl/sharedStrings.xml` (ячейка `<c t="s"><v>17</v></c>` ссылается индексом на `<si>` под
номером 17). Поэтому:
- **Основная обрабатываемая часть — `xl/sharedStrings.xml`**, группа = одна запись `<si>`,
  units — все `<t>` внутри неё (простой `<si><t>` и rich text `<si><r><t>…` покрываются
  единообразно; токен, разорванный между `<r>`, собирается ядром так же, как в docx).
- **Дополнительно — inline-строки** `<is>` внутри `<c t="inlineStr">` в
  `xl/worksheets/sheet*.xml` (группа = одна `<is>`, units — `<t>` внутри неё). Лист без
  inline-строк не переписывается — переносится байт-в-байт через `rewrite_zip`.

Мы обходим только `<t>` **внутри** `<si>`/`<is>`, поэтому `<v>` (число/индекс) и `<f>`
(формула) в units не попадают и не трогаются. Атрибуты `t`/`s` у `<c>`, `xl/styles.xml`,
`count`/`uniqueCount` у `<sst>` не читаются и не изменяются — за счёт этого стиль ячейки,
формат числа и тип ячейки сохраняются автоматически, а токен-строка остаётся строкой
(ИНН/счёт/телефон не конвертируются в число и не теряют ведущие нули). Проверено
эмпирически на синтетическом `.xlsx`, собранном вручную через `zipfile` (`openpyxl` не
используется): простой `<si>`, rich text с токеном, разорванным между двумя `<r>`, inline-
строка в листе, общий `<si>` на две ячейки, неизвестный токен, целостность формулы,
`<v>`-индекса, стилей и `count`/`uniqueCount`.

## Публичный интерфейс
```python
from xlsx_rewriter import rewrite

def rewrite(src_path: str, dst_path: str, resolve: Resolver) -> list[str]: ...
```
`Resolver` — тот же тип, что в блоке 8 (`Callable[[str], str | None]`), не переопределяется,
импортируется из `ooxml_core`.

Минимальный пример:
```python
from xlsx_rewriter import rewrite

mapping = {"[ORG_1]": "ООО «Ромашка»", "[INN_1]": "7701234567"}
unresolved = rewrite("ответ.xlsx", "ответ_restored.xlsx", lambda tok: mapping.get(tok))
# ответ_restored.xlsx создан на диске; unresolved -> [] (если все токены известны)
```

Исключения:
- `OoxmlError` (`ooxml_core`) — если `src_path` не ZIP/повреждён/zip-бомба. Пробрасывается
  из `read_zip_parts` без изменений.
- `FileNotFoundError` — если `src_path` не существует. Пробрасывается из `read_zip_parts`
  без изменений (стандартное исключение Python, не оборачивается).
- `lxml.etree.XMLSyntaxError` — если целевая часть архива не well-formed XML (не ожидается
  для настоящих OOXML-файлов, не перехватывается и не маскируется).
- Исключения из переданного `resolve`, если он их бросает, — не перехватываются (тот же
  контракт, что у `replace_tokens_in_group` в блоке 8).

## Формат данных на выходе
`rewrite(...)` возвращает `list[str]`, например `["[ORG_99]"]` или `[]`. Побочный эффект —
файл `dst_path` создан на диске (тот же набор и порядок записей архива, что в `src_path`;
`compress_type`/`date_time` сохранены для не тронутых блоком 11 частей).

## Инварианты выходных данных
- unresolved — **в порядке первого появления**: сначала по `xl/sharedStrings.xml` (в
  порядке `<si>`), затем по листам `xl/worksheets/sheet*.xml` (по возрастанию числового
  номера в имени — `sheet2.xml` перед `sheet10.xml`, сравнение числом, а не строкой),
  внутри листа — `<is>` в порядке дерева, внутри группы — `<t>` в порядке следования.
  Повторы возможны (дедупликацию делает блок 12).
- Части архива вне обработки (`xl/styles.xml`, `xl/workbook.xml`, `xl/charts/*`,
  `xl/pivotTables/*`, темы, изображения, `[Content_Types].xml`, листы без inline-строк) —
  байт-в-байт идентичны исходным (проверено на `xl/styles.xml`, `xl/workbook.xml`).
- Атрибуты `count`/`uniqueCount` у `<sst>` **не пересчитываются** (число записей мы не
  меняем, только содержимое) — проверено, остаются исходными.
- Тип ячейки (`t`), индекс стиля (`s`), `<v>` (число/индекс sharedStrings) и `<f>`
  (формула) не изменяются — проверено побайтно на конкретных ячейках. Токен, оказавшийся
  в тексте формулы, **не** раскрывается и **не** попадает в unresolved (мы туда не смотрим).
- Оформление (`<rPr>`, шрифты, цвета, заливки, форматы числа) не читается и не изменяется —
  гарантия ядра (блок 8); единственный атрибут, который ядро может добавить, —
  `xml:space="preserve"` на узле `<t>`, чей итоговый текст начинается/заканчивается пробелом.
- Один `<si>`, на который ссылается несколько ячеек, раскрывается один раз и корректно
  «виден» во всех ячейках (общие строки не дублируются) — проверено (si0 → B2 и его же
  токен в si4).

## Что блок ожидает на входе (предусловия)
- `src_path` — путь к файлу, который **является** OOXML-контейнером (проверяет `OoxmlError`
  ядро; блок 11 сам расширение не проверяет — этим занимается блок 12).
- Внутри частей — валидный SpreadsheetML: `<si>`/`<is>` содержат `<t>` c текстом в `.text`
  (может быть `None` → трактуется как `""`). Нестандартная структура от экзотического
  генератора не тестировалась за пределами того, что производят Excel/openpyxl.
- `resolve` — чистая функция, вызывается многократно, слева направо, отдельно на группу.

`openpyxl` **не** в `sys.modules`.

- Python: `Python 3.11.9` (`venv/Scripts/python.exe --version`).
- Внешние зависимости: только то, что тянет `ooxml_core` (`lxml`) — блок 11 сам новых

## Соглашения о путях и файлах времени выполнения
Блок не владеет постоянными путями. Пишет ровно один файл — `dst_path`, через
`ooxml_core.rewrite_zip` (временный файл создаётся и публикуется этой функцией, см.
HANDOFF_8). Других файлов/директорий не создаёт.

## Отклонения от спецификации
Отклонений нет. Уточнения реализации (в рамках спеки):
- Числовой (не строковый) порядок сортировки имён `sheet*.xml` — спецификация требует
  «затем по листам»; при строковой сортировке порядок ломается на книгах от 10 листов
  (`sheet10.xml` встал бы перед `sheet2.xml`). Сравнение по извлечённому числу гарантирует
  документный порядок unresolved.
- Лист без единой inline-строки не помещается в `modified` (не переписывается), чтобы
  сохранить его байт-в-байт: подавляющее большинство листов ссылается на sharedStrings и
  вообще не содержит `<is>`, переписывать их незачем.

## Предложения по изменению интерфейсов
Нет. Зафиксированный интерфейс реализуем как есть.

## Известные ограничения / TODO
**Ответ на обязательный вопрос компонента — что мой блок гарантированно не портит и
чего он в принципе не видит:**
- **Гарантированно не портит** (потому что не касается): `xl/styles.xml`, атрибут `s` и
  `t` у `<c>`, `<v>` (числа и индексы sharedStrings), `<f>` (формулы), `count`/`uniqueCount`
  у `<sst>`, ширины колонок, условное форматирование, диаграммы (`xl/charts/*`), сводные
  таблицы (`xl/pivotTables/*`), темы, изображения, `[Content_Types].xml`; структуру `<si>`/
  `<r>`/`<is>` (узлы не удаляются, меняется только `.text` у `<t>`); листы без inline-строк
  (байт-в-байт). Тип ячейки сохраняется → токен-строка остаётся строкой (ИНН/счёт/телефон
  не превращаются в число, ведущие нули и длинные номера не теряются).
- **В принципе не видит:** токены в формулах `<f>` (осознанно не обрабатываются и не идут
  в unresolved); текст в мастерах/шаблонах не применим к xlsx; искажённые LLM токены
  (`[org_1]`, `ORG_1`, `[ORG 1]`) — не распознаёт (тот же `TOKEN_RE` ядра, что у блока 6);
  текст внутри встроенных объектов/диаграмм (`xl/charts/*`, `xl/drawings/*`) — вне
  описанных частей архива.
- **Осознанные ограничения:**
  - **Сохранение типа ячейки — осознанное решение, а не недоработка.** После замены токен-
    строка остаётся строкой даже если значение выглядит как число (`[INN_1]` → `7701234567`);
    `t` и `s` не меняются. Конвертировать в числовую ячейку запрещено — Excel съел бы
    ведущие нули и перевёл длинные номера в экспоненту, испортив данные.
  - **Токен в формуле** (`<f>`) не раскрывается и в unresolved не попадает.
  - **Фонетические подсказки** (`<rPh>` внутри `<si>`, восточноазиатский кейс) содержат
    свои `<t>`; спецификация предписывает брать «все `<t>` внутри `<si>`», поэтому такие
    `<t>` формально попадают в группу. Для целевого (русскоязычного) сценария `<rPh>` не
    встречается; токены в фонетических подсказках не ожидаются. Если бы они там были,
    изменение длины базового текста могло бы рассинхронизировать смещения `sb`/`eb` —
    зафиксировано как известное ограничение, вне целевого сценария.

## Данные для тестов
Реально проверенные сценарии (`venv/Scripts/python.exe`, синтетический `.xlsx`, собранный
вручную через `scratch_test_block11.py`, т.к. `openpyxl` использовать запрещено):

1. **Простой `<si>`.** `<si><t>[ORG_1]</t></si>`, `resolve("[ORG_1]") -> "ООО «Ромашка»"`
   → текст `<si>` стал «ООО «Ромашка»».
2. **ИНН остаётся строкой.** `<si><t>[INN_1]</t></si>` → `"7701234567"`; ячейка B2/C2
   сохранила `t="s"`, `s="1"`, `<v>`-индекс не тронут (проверено: B2 `<v>` == `"0"`).
3. **Rich text, токен разорван между двумя `<r>` (граничный).**
   `<si><r><rPr>…красный,14,b…</rPr><t xml:space="preserve">[PHONE</t></r><r><t>_1] доб. 5</t></r></si>`,
   `resolve("[PHONE_1]") -> "+7 495 123-45-67"` → склеенный текст `<si>` стал
   `"+7 495 123-45-67 доб. 5"`; оформление первого `<r>` (`<rPr>`) не изменилось.
4. **Inline-строка в листе.** `<c t="inlineStr"><is><t>inline [INN_1] tail</t></is></c>`
   → `"inline 7701234567 tail"`; `t="inlineStr"` сохранён.
5. **Общий `<si>` на две ячейки.** Тот же `[ORG_1]` в si0 и si4 (обе раскрыты; общие
   строки не дублировались).
6. **Неизвестный токен (граничный).** `"Нет в сессии: [ORG_99]"`, `resolve` не знает
   `[ORG_99]` → текст не изменился ни в одном символе, `unresolved == ["[ORG_99]"]`.
7. **Формула не тронута (граничный).** `<f>SUM(A1:A2)+[ORG_1]</f>` → текст формулы после
   `rewrite` идентичен; `[ORG_1]` в формуле не раскрыт и в unresolved не попал.
8. **`count`/`uniqueCount` не пересчитаны.** `<sst count="6" uniqueCount="5">` — оба
   атрибута после `rewrite` исходные.
9. **Сохранность частей и архива.** `xl/styles.xml` и `xl/workbook.xml` байт-в-байт;
   `namelist()` входа и выхода совпадают; `zipfile.testzip()` выхода → `None`.
