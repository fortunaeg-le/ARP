## Что за проект

SHIFRATOR — локальный офлайн-инструмент на Python 3.11: находит конфиденциальные
данные (ПДн, реквизиты) в тексте договора, заменяет их обратимыми токенами `[TYPE_N]`
перед ручной отправкой текста в стороннюю LLM и восстанавливает исходные значения в
ответе LLM — как в тексте (`decrypt`), так и в принесённом файле `.docx/.xlsx/.pptx`
с сохранением оформления (`decrypt-file`, компонент 2).

**Главный риск всей системы — тихая утечка ПДн:** текст, в котором детекторы что-то
пропустили, уходит в LLM без единого предупреждения. Любое изменение детекторов /
токенизатора оценивать в первую очередь по этому риску.

## Структура и запуск

```
shifrator.py          # CLI: python shifrator.py encrypt|decrypt|delete|decrypt-file …
entity_types.yaml     # конфиг сущностей — лежит рядом с shifrator.py (контракт CLI)
src/                  # все библиотечные модули, ПЛОСКИЕ имена импортов (from models import …)
tests/                # pytest; tests/component2/ — тесты компонента 2
docs/                 # спеки, HANDOFF-архив, отчёты
```

- Запуск CLI: `venv/Scripts/python.exe shifrator.py encrypt <файл.docx|.txt>` — из корня.
- Тесты: `venv/Scripts/python.exe -m pytest tests/ -q`. Ожидаемо: **268 passed, 1 xfailed,
  1 failed** — упавший тест `tests/component2/test_e_malformed_input.py::test_valid_zip_
  without_any_target_part_raises_ooxml_error` намеренно красный (пин незакрытого дефекта,
  см. `docs/reports/COMPONENT2_TEST_REPORT.md`); xfail — осознанно отложенный B4 (омоглифы).
- `src/` попадает на `sys.path` тремя путями: editable-установка в venv (уже сделана;
  при пересоздании venv — `pip install -r requirements.txt`, затем
  `pip install -e . --no-build-isolation`), корневой `conftest.py` (pytest), bootstrap в
  `shifrator.py` (CLI). Плоские импорты — контракт; не превращать `src/` в пакет.

## Что работает (реализовано и покрыто тестами)

- Блоки 1–7: extract (.docx/.txt) → detect_regex + detect_ner (Natasha) → tokenize
  (разрешение пересечений, B3-проход по граничным окнам сегментов) → save_session
  (Fernet, `~/.shifrator/sessions/{sid}.enc`, ключ `key.bin`) → CLI encrypt/decrypt/delete.
- Контракт CLI `encrypt`: анонимизированный текст пишется в `{storage_dir}/{sid}.txt`,
  в stdout — ТОЛЬКО session_id.
- Компонент 2 (блоки 8–12): `decrypt-file` раскрывает токены в принесённом
  `.docx/.xlsx/.pptx` по XML-узлам на месте (ядро `ooxml_core` + 3 адаптера + фасад),
  включая токены, разорванные между run'ами; оформление сохраняется.
- Все правки трёх раундов тестирования: FINDINGS #1–#7, #9, #10 — FIXED; B1 (ReDoS SUM),
  B2 (реквизиты с пробелами), B3 (сущности на границе сегментов), B5 (UTF-16 без BOM →
  явная ошибка), B6 (сайдкар .txt при delete/purge) — FIXED.

## Что нельзя трогать ни при каких обстоятельствах

- `~/.shifrator/` (реальное хранилище пользователя): дефолтный путь, имя `key.bin`,
  форматы имён `{sid}.enc` / `{sid}.txt`. Любое изменение делает существующие сессии
  невосстановимыми. В тестах — только `tmp_path` (подмена `USERPROFILE`/`HOME` для CLI).
- Способ запуска `python shifrator.py …` и контракты вывода/кодов возврата CLI.
- Существующие тесты (регресс чинить в коде, не в тестах).
- Плоские имена импортов модулей `src/`.
