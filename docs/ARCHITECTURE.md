# ARCHITECTURE — кто за что отвечает и что нельзя ломать

Уровень документа: **модуль делает то-то, вызывается оттуда-то, контракт такой.**
Построчного разбора здесь нет — источник истины всегда код; если код разошёлся с
текстом, прав код, а этот файл чинится.

Текущее состояние и открытые дефекты — НЕ здесь, а в [STATE.md](STATE.md) и
[FINDINGS.md](FINDINGS.md). Историческая доказательная база (цифры, репро,
методики) — `docs/archive/`, оглавление переездов — [DOC_REGISTRY.md](DOC_REGISTRY.md).

## 1. Конвейер: от файла до восстановления

### encrypt (`shifrator.py:cmd_encrypt`, он же путь интерфейса и замера)

```
extract(path)                     src/extractor.py
    .docx/.txt → SourceDocument: сегменты + detection_text (нормализация регистра)
scan_unread_zones(path)           src/unread_zones.py
    зоны .docx, которые extract НЕ читает (колонтитулы, сноски, надписи,
    вложенные таблицы). strict (умолчание) → таблица на stdout + exit 2, сессии нет
run_detection(doc, config)        src/pipeline.py   ← ЕДИНСТВЕННАЯ копия порядка
tokenize(doc, entities, cfg)      src/tokenizer.py
    разрешение пересечений + B3-проход + ФИЛЬТР ТИПОВ + присвоение токенов
save_session(...)                 src/session_store.py через src/storage.py
    Fernet → {sid}.enc; в stdout — ТОЛЬКО session_id, анон-текст в {sid}.txt
```

### decrypt / decrypt-file

```
detokenize(text, sid)             src/detokenizer.py     — [TYPE_N] → значение в тексте
detokenize_file(sid, path, out)   src/file_detokenizer.py
    → *_rewriter (docx/xlsx/pptx) → src/ooxml_core.py: ZIP+XML, замена токенов
      в группе run'ов (в т.ч. разорванных между ранами), защита от zip-бомб
    результат: {имя}_restored.{ext}, оформление сохранено
```

`encrypt` умеет `.docx/.txt`; `decrypt-file` — все три формата OOXML.

**Почему `pipeline.run_detection` вообще существует.** Порядок шагов детекции был
продублирован руками в трёх местах — CLI, интерфейс, замер корпуса. Копия в
`app/core.py` однажды отстала на целый этап: интерфейс не давал ORG-меток, хотя
CLI давал. Теперь порядок живёт в одной функции, и разъехаться структурно нельзя.

## 2. Слои детекции и их порядок

Порядок в `src/pipeline.py:run_detection` — не стилистика, каждый шаг опирается на
предыдущий:

| # | Шаг | Модуль | Зачем именно здесь |
|---|---|---|---|
| 1 | `detect_regex` + `collect_multispan` | `regex_detector.py`, `multispan.py` | Реквизиты считаются ПЕРВЫМИ: дают «карту занятой территории» барьером расширению адреса и питают структурный движок (ИНН-10 → ORG, ИНН-12/СНИЛС → PER). `multispan` собирает рваные PHONE/ACCOUNT/BIRTHDATE |
| 2 | `detect_structural` | `anchor_registry.py` | ORG и PER одним движком-реестром: якорь → арбитраж типа ключа по лемме ядра → проход 2 по падежам. **Natasha-ORG и Natasha-PER в конфиге выключены**, оба типа только структурные |
| 3 | `detect_ner` | `ner_detector.py` | ТОЛЬКО адрес (`natasha.AddrExtractor` + маркеры + yargy в окне). Готовые ORG/PER-спаны передаются барьером |
| 4 | `suppress_conflicts` | `anchor_registry.py` | Снимает адрес, целиком накрытый ядром ORG |
| 5 | `merge_compound_entities` | `syntax_compound.py` | «ИП» + «Пирогова А.С.» → один ORG по направлению ребра appos |
| 6 | `detect_negative_classes` | `anchor_registry.py` | `ROLE_TERM`/`COLLECTIVE` — БЕЗ префикса токена: не маскируются, работают только барьером в разрешении пересечений |

**Якорная модель (этапы A/B/C).** ORG, PER и ADDRESS ловятся не «моделью по
тексту», а структурой: сначала строгий якорь (форма юрлица, кавычки, реквизит,
адресный маркер), потом реестр, потом второй проход по падежным формам того же
ключа. Это и дало обвал ложных срабатываний: ложных ADDRESS 3483 → 14, ложных PER
11 → 1, мусорных ORG на реальном договоре 2834 → 70.

**Отрицательные классы** (`CLAUSE_REF`, `ROLE_TERM`, `COLLECTIVE`) объявлены в
`entity_types.yaml` с `suppress_masking: true` и без `token_prefix`: детектор их
находит, маска не ставится, но они занимают территорию и не дают PER/ORG
проглотить «Стороны», «Исполнитель», «п. 4.2». Эталонных записей у них 0 —
по конструкции, а не по недосмотру.

## 3. Арбитраж пересечений

Живёт в `src/tokenizer.py:_resolve_overlaps`. Пока есть пересекающаяся пара:
выбирается глобально сильнейший (`_winner`), фиксируется, и все, кто пересекается
именно с ним, **обрезаются** до непересекающейся части (`_trim_to_free`), а не
выбрасываются целиком.

Порядок сравнения `_winner`: механизм (regex > ner) → длина → приоритет типа.
Списки приоритетов — в коде, **не** в YAML:

- `_REGEX_PRIORITY`: `BANK_ACCOUNT, OGRN, INN, INN_PERSON, BIK, SNILS, KPP,
  PASSPORT, PHONE, SUM, EMAIL, BIRTHDATE, DATE, PERCENT, TERM`
- `_NER_PRIORITY`: `ADDRESS, ORG, PERSON`

`assert_priority_contract` (там же) роняет сборку, если тип с `token_prefix`
появился в YAML, но не попал ни в один список: забытый тип иначе молча становится
слабее всех и проигрывает каждое пересечение. Шесть будущих якорных типов этапа
T3 обязаны быть внесены явно.

## 4. Наборы типов и фильтр маскирования

`src/type_policy.py` — единственное место, где решается, ЧТО маскировать.
Интерфейс своего состава наборов не хранит.

| Набор | Состав |
|---|---|
| `personal` | `PERSON, ADDRESS, PHONE, EMAIL, PASSPORT, SNILS, BIRTHDATE, INN_PERSON` |
| `personal_requisites` | + `INN, OGRN, KPP, BIK, BANK_ACCOUNT, ORG` |
| `with_money` | + `SUM, PERCENT, TERM` |
| `maximum` | сентинел `None` = все типы с `token_prefix`. Замер и гейт считаются только на нём |

`INN` (10 цифр) — организация, не ПДн; `INN_PERSON` (12 цифр) — человек.
Разделение по ТИПУ, а не по длине внутри одного типа, — потому что набор «только
персональные» иначе вынужден исключать ИНН целиком, и ИНН предпринимателя
остаётся в тексте открытым.

Фильтр применяется в **одной** точке — `tokenizer.apply_masking`. Дорогая часть
(`resolve_for_masking`) от набора не зависит: переключение набора не меняет
детекцию, только маскирование. Умолчание — `personal`; при апгрейде со следами
прежней работы, но без файла настроек, форсируется `maximum`, чтобы не сузить
молча уже привычное пользователю поведение (`ensure_settings`).

## 5. Гейт: семь линий

`tests/corpus/gate.py`, допуски — `tests/corpus/gate_config.py`, счёт — `measure_lib.py`.
Точка отсчёта — `tests/corpus/results_baseline.json`. `bench/` — **не** гейт.

| Линия | Что мерит | Допуск |
|---|---|---|
| **а** precision | Точность по эталону каждого типа; FP = маска на объявленном негативе | `PRECISION_TOLERANCE_PP = 0.0` |
| **б** leak_v2 | Частичная утечка по каждому типу и по агрегату, два порога (≥6, ≥8 символов) | `LEAK_V2_TOLERANCE = 0` |
| **в** masking A | Round-trip: восстановление байт-в-байт. Обязана быть РОВНО 100% | `MASKING_A_TOLERANCE_PP = 0.0` |
| **г** masking B | Эталонная сущность закрыта масками целиком | `MASKING_B_TOLERANCE_PP = 0.0` |
| **д** порча документа | Маски, не легшие ни на эталон, ни на негатив | `OVERMASK_NOTHING_TOLERANCE = 0`, уровень — журнал `overmask_ledger.json` |
| **е** границы по направлению | Недобор (утечка) и перебор (порча) РАЗДЕЛЬНО | `BOUNDARY_UNDER/OVER_TOLERANCE = 0` |
| **ж** зеркало подавления | Эталонные сущности, погашенные отрицательным классом — безусловный 0 | допуска нет |

Плюс независимые условия: крешей 0, `FP_TOLERANCE = 0` на негативах, сверка
`MANIFEST.sha256` до и после прогона, известный долг ADDRESS не растёт
(`docs/known_leaks_stage_c.json`).

Мягкая **masking C** (тип маски == тип эталона) печатается, но гейт не роняет.
Она же — историческая ловушка: «90% корректности» по C было фикцией, пока метрика
была слепа к over-masking; линия «а» появилась именно поэтому.

**Две ошибки границ имеют разную цену**, и линия «е» разделена по ней: недобор =
часть значения осталась открытым текстом (утечка ПДн), перебор = съеден соседний
текст (порча документа). Агрегат их смешивал.

`promote_baseline.py` — единственная санкционированная дорога к движению точки
отсчёта: оценивает дамп действующим гейтом, требует `--author`/`--reason` при
росте линии «д», отказывается вообще при красноте любой другой линии, дописывает
запись в журнал и пересобирает манифест.

| | v1 `tests/corpus/` | v2 `tests/corpus_v2/` |
|---|---|---|
| Объём | 324 документа (162 `.txt` + 162 `.docx`) | 138 документов (54 `.txt` + 84 `.docx`) |

| Роль | Регресс-гейт, заморожен | Замер новых типов (MONEY/PERCENT/TERM), оси форм |
| Манифест | `MANIFEST.sha256`, 659 строк | `MANIFEST.sha256`, 285 строк |

Быстрый набор — `subsample.py` по фиксированному списку `subset_iter.json`
(33 документа). У него **своя** точка отсчёта `results_iter_baseline.json`, и его
вывод — находка, а не приёмка.

> **Цифры на порождённом корпусе — верхняя граница, а не измерение.** Генератор
> писал и текст, и эталон; конструкция, которую он не предусмотрел, не появится ни
> в тексте, ни в разметке, и её отсутствие будет невидимым.

**Стена.** Ни один модуль `src/` не импортирует `tests/corpus_v2/values.py`,
`generate.py` и эталон. Держится дисциплиной и проверкой чтением: исполняемого
теста-стража на импорт-граф **нет** — это открытый долг, не гарантия.

**TRANCHE** объявлен неизмеримым (37 вхождений, 5 форм, ни одного числа) и
детектору не подлежит; на это стоят четыре сторожа, включая автособираемый
`tests/test_corpus_v2_axis_coverage.py`.

## 7. Интерфейс и хранение

`app/` — десктопный пилот: stdlib `http.server` (`server.py`), логика в `core.py`,
один `index.html`, отчёт качества в `report.py`, лаунчер и self-check моделей в
`launcher.py`/`selfcheck.py`. Только `127.0.0.1`, ноль сетевых зависимостей.
Цикл: шифрование → **экран проверки** (правка границ и типов, ручная разметка
пропущенного) → восстановление. Экран проверки — центр интерфейса.

Хранение: `src/session_store.py` (Fernet-шифрование токен-мапы, `{sid}.enc`, ключ
`key.bin`, TTL 24 ч, автоочистка просроченных) под тонким интерфейсом
`src/storage.py` — CLI и интерфейс ходят туда, а не в `session_store` напрямую.
Разметка живёт отдельно (`~/.shifrator/markup/`, срок 30 дней) и переживает
удаление сессии.

**Ключ атомарен и не пересоздаётся при чтении:** `key.bin` создаётся только в
`save_session`; `load_session`/`purge_expired` при отсутствии ключа кидают ошибку,
а не генерируют новый — тихое пересоздание похоронило бы все прочие сессии.

**Отчёт наружу безопасен по построению**, тремя рубежами: белый список полей
(структурные коды вместо текста), нормализация входных строк в коды словаря и
структурный часовой `assert_structural` — каждая строка отчёта обязана быть
схемным ключом, кодом словаря, ISO-датой или дословной константой модуля; иначе
отчёт не отдаётся вообще.

## 8. Инварианты, которые нельзя ломать

**`original_text` == точный срез `segment.text[start:end]`.** На этом держится
посимвольное восстановление. Нарушение — не исключение, а тихая порча текста.

**Пересечение разрешается обрезкой, не выбросом.** Если проигравший нёс ПДн вне
зоны пересечения (адрес слева от regex-ИНН), выброс целиком отправлял этот хвост
в открытый текст. Зона пересечения закрыта токеном победителя — там утекать нечему.

**Разделитель граничного окна B3 ≠ разделитель сборки текста.** `" | "` между
ячейками — только в читаемой сборке. В окне детекции соседние ячейки одной строки
склеиваются пустой строкой `""`: `" | "` физически разрывает паттерны, и
ИНН/телефон, порванный границей ячеек, перестаёт матчиться.

**Половины B3-пары получают РАЗДЕЛЬНЫЕ токены.** Каждая половина — обычная
независимая `Entity` со своим `original_text`. Общего реестра пар нет. Так ложное
срабатывание B3 остаётся терпимо-шумным вместо разрушительного.

**Составные сущности (этап B) ≠ B3.** B3 сшивает ОДНУ сущность, разорванную
границей сегмента, внутри `tokenize`. Этап B сливает ДВЕ разнотипные сущности
внутри одного сегмента, отдельным проходом до `tokenize`.

**Барьеры расширения адреса.** Реквизиты и структурные ORG/PER передаются в
`detect_ner` как карта занятой территории; расширение адреса на них не наступает.

**Регистр — признак имени собственного для Natasha.** Экстрактор строит
`detection_text` с нормализацией регистра и наследованием caps от стилей абзаца,
иначе ФИО в нестандартном регистре не ловятся вовсе.

**Плоские импорты `src/`** — не превращать в пакет. Три пути на `sys.path`:
editable-установка в venv, корневой `conftest.py`, bootstrap в `shifrator.py`.

**Корректность маскирования только растёт.** Асимметрия ошибок: пропуск человек
поймает на экране проверки, кривую маскировку — нет.

## 9. Отвергнутые решения (не переоткрывать)

| Отвергнуто | Почему |
|---|---|
| Выбрасывать проигравшего при пересечении целиком | Хвост с ПДн вне зоны пересечения уходил в открытый текст (дефект W2-D1) |
| Общий токен обеим половинам B3-пары через реестр пар | Порча данных при восстановлении; принят «Вариант А» — раздельные токены |
| Склейка «PER рядом с ORG» в любую сторону; фильтр по списку ролевых слов | «Свидетель Иванов И.И. ООО «Ромашка»» схлопывалось в одну ORG, ФИО исчезало. Принят синтаксический критерий — направление ребра appos |
| Считать «директор Иванов» организацией | Человек здесь представитель, а не сторона. В ORG сливается только «ИП/юрлицо + ФИО» |
| Гонять yargy-парсер адреса сканером по всему документу | yargy был доминантой времени (~256 c из 277 c) при низкой полноте спана. Принято: место подтверждают дешёвые LOC-спаны + маркеры, yargy добирает спан только в окне с хитом |
| Разделитель `" \| "` внутри окна детекции B3 | Разрывает паттерны реквизитов |
| GLiNER вместо Natasha как генератор кандидатов | Теряет ≥19% recall на чистой синтетике и удваивает over-masking родовых слов. Отдельный ярус recall — возможен, замена — нет |
| Контрольная сумма СНИЛС | Сознательно не реализована: три причины в отчёте этапа 3 |
| Двигать планку гейта копированием файла | Не остаётся ни автора, ни причины; дифф на сотни тысяч строк JSON нечитаем. Только `promote_baseline.py` |

**Осознанно отложено:** омоглифы в цифрах реквизитов (B4, `xfail(strict)`);
`encrypt` для `.xlsx/.pptx` (реализован только `decrypt-file`); извлечение PDF;
веб-компонент.
