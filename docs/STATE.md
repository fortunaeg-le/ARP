## 2. Ускорение прогонов — два независимых механизма

**Гейт/корпус-харнесс (этап SPEED, 2026-08-04).** `run_measurement.run_all`
параллелит ПО ДОКУМЕНТАМ через `multiprocessing.Pool`, плюс кеш разбора
`entity_types.yaml` (`src/config_cache.py`). Флаг `--workers N` в
`gate.py`/`subsample.py`, умолчание — авто по ядрам/памяти. Разбор —
[`JOURNAL.md`](JOURNAL.md), запись SPEED.

**pytest (этап TESTOPT, 2026-08-05).** `pytest.ini`: `-n auto` в `addopts`
(`pytest-xdist` 3.8.0 + `execnet` 2.1.2, тестовая зависимость, не в
`requirements.txt`). ~72 % времени набора — легитимные подпроцессные тесты
(поведение в отдельном процессе — сам предмет проверки: вложенный pytest
блоков 1-7, CLI-подпроцессы `shifrator.py`), их распараллелить нельзя без
подмены того, что проверяется; экономия целиком из распараллеливания
ОСТАЛЬНЫХ ~28 % по ядрам воркеров xdist. Вложенный регресс-тест закреплён
за одним процессом явно (`-n 0` в его собственном `subprocess.run`) —
задаёт нижний предел ~334 с, см. §1.

Изоляция под xdist проверена перед включением (порты, порядкозависимость,
общие пути на диске) — 5 полных прогонов побитно идентичны. При проверке
найден и починен НА УРОВНЕ ТЕСТА (не `src/`, см. §6) баг кеширования
`Path.home()` в `session_store.py`, из-за которого два теста писали
сессии мимо `tmp_path` в реальный `~/.shifrator`.

Разбор обеих оптимизаций, замер памяти (xdist: ~4.3-5.5 ГБ на 28-39
процессов при 18 ГБ свободных), таблица «где время» и список неприменённых
кандидатов с измеренной ценой — [`JOURNAL.md`](JOURNAL.md), запись TESTOPT.
