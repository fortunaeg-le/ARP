## 2. Что принёс LAYOUT

**Ремонтный проход** — второй, дополнительный вид текста с вылеченными
вёрсточными разрывами (выброшены с картой индексов) и второй проход штатных
детекторов по нему; маска в исходных координатах. Монотонное дополнение:
основной вид не меняется, ремонт может только добавить (страж — исполняемый
тест, не свойство конструкции). Два места:

| Где | Что лечит |
|---|---|
| `src/layout_repair.py` из `pipeline.run_detection` (шаг 7) | разрыв ВНУТРИ сегмента: `\n` (w:br / стык абзацев ячейки) и NBSP/NNBSP внутри токена |
| шаг 3a′′ в `tokenizer._detect_boundary_entities` | разрыв ГРАНИЦЕЙ сегментов: шовный `\n` окна B3 выброшен, эмит парой половин (контракт B3) |

Правила различения «мягкий разрыв vs граница» (несущие, не эвристика):
лечится только разрыв внутри токена; PERSON — только буква слева + строчная
справа; regex-типам разрешён край `@ . -`; `\n\n` — граница абзацев, никогда;
`_` — не край значения (линия подписи). Приём находки: спан накрывает
ремонтную позицию; накрытая основной сущностью позиция ремонта не запускает
(чистый документ — ноль работы); поглощение запрещено regex-типам и разрешено
PERSON только полным накрытием своей же частичной находки; ORG/ADDRESS через
ремонт не эмитятся. **Сборка через `\n` строже посегментной детекции**
(`_strict_seam_ok`, правило A6): КС сходится всегда (даже под якорем), голая
цифровая цепь — только под якорем типа.
