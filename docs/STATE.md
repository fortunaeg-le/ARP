## 2. Этап A6 — класс «вёрстка рвёт значение» закрыт сборкой, не паттернами

Механизм: **сборка цепи цифровых групп через стык граничного окна B3**
(`multispan.collect_seam_entities`, вызывается из
`tokenizer._detect_boundary_entities`) плюс обобщение внутрисегментного
мультиспана (`collect_multispan`, секция «б») на общую декларацию
`_SEAM_TYPES`: ACCOUNT (20 цифр), OGRN (13/15 + КС), INN (10 + КС), INN_PER
(12 + КС), SNILS (11), BIRTHDATE (`_BDATE`-паттерны). Стражи направления
ошибки: якорь обязателен ВСЕМ (жёстче посегментной детекции), сумма цифр
точно равна длине ОДНОГО значения (два значения в столбик → отказ целиком,
под-окон нет), КС где определена, и **ни одна сторона `\n`-разрыва не целое
валидное значение сама по себе** (формализация урока `A2-NEWLINE-CROSS`:
целый ОГРН-13 + случайные «71» не станут ОГРНИП-15). Стыки ячеек одной строки
(sep `''`) не трогаются — их склеивает само окно для штатного regex.

**Инвариант A6 (`pipeline.py`): рваный реквизит — валидная маска, но НЕ
доказательство имени.** Мультиспан-сущности структурному движку не подаются:
name-run в `\n`-вырезанном виде ORG дотягивается до чужих слов
(`A6-REQ-NAMERUN-OVERREACH`, латентно и на чистых документах).

**Немаскируемый символ стыка.** Собранное через стык значение делится на пару
Entity_A/Entity_B по контракту B3; `\n` между сегментами не принадлежит ни
одному из них — маскировать его нечем. Метрика честно считает недобор 1 символ
на сборку: отсюда ВСЕ красные (г)/(е)-недобор строки гейта (+105 сборок).
Принято владельцем до кода как механика метрики.

**Ограничения, замеренные до начала работ:** двойной разрыв (значение через
ТРИ сегмента) не собирается — корпус: 2 сущности из ~11 600 (обе
`sale_0002__m1337_linebreak`), реальный документ: 0. Рваный сам ЯКОРЬ
(«р/»+«с 407028…») не защитывается — единицы, класс в
`A6-DESTRUCTIVE-TRANSFORMS` п. 5/7.
