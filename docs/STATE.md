**Ключевое отличие от A1:** целевой документ (`C:\shifrator_real\dog.docx`,

встречается дважды, но оба раза в определительной прозе, без числа рядом.
Формы для правки взяты из общей практики оформления российских договоров, а
не из целевого документа — само задание это явно требовало.

| Тип | Правка (`entity_types.yaml`) | Корпус v1 (было→стало) | Реальный документ (было→стало) |
|---|---|---|---|
| код подразделения (`:145`) | зазор `{0,10}→{0,25}`; ПОПУТНО ПОЧИНЕН якорь — «код подр.» было заявлено комментарием, не работало кодом, теперь работает | leak_v2≥6 `266→264` (улучшение), 0 новых FP | 0→0 (якоря в документе нет) |
| СНИЛС (`:171`) | зазор `{0,20}→{0,30}`; официальная формулировка «...государственного/обязательного пенсионного страхования» добавлена В ЯКОРЬ | без изменений (корпус v1 не содержит новых форм) | 0→0 (якоря в документе нет) |
| дата рождения (`:201`) | зазор `{0,10}→{0,35}`; день/месяц/год разделитель `[.\/]→[.\/-]` (дефис для полноты класса, реально НЕ работает — нормализация схлопывает дефис между цифрами ДО детекции, см. `A2-BIRTHDATE-HYPHEN-DEAD` в комментарии на месте) | без изменений | 0→0 (якорь есть дважды, оба раза без числа рядом) |

**Внутренние разделители значений (дефис/пробел между группами цифр внутри
самого значения) НЕ расширены на `\s?`/NBSP** — первая попытка (для года
BIRTHDATE) дала измеренную РЕГРЕССИЮ на корпусе v1 (4 документа мутации
`linebreak`: было 0 масок на документ, стало 2 разорванных куска — недобор
границ `660→664`). Причина: `\s` матчит не только перенос строки внутри
прозы, но и структурную границу сегмента — то, что проект уже сформулировал
как правило для INN/OGRN/ACCOUNT/BIK/KPP (`entity_types.yaml:32-36`, «не `\s`,
чтобы не сшивать значения через перенос строки»), но не применил
последовательно везде. Откачено для всех трёх типов A2. Находка
`A2-NEWLINE-CROSS` фиксирует, что то же самое ещё не проверено для паспортной
серии (A1) и для `PHONE` (все четыре разделителя которого — bare `\s`).

**anti_anchor — новый механизм (`src/regex_detector.py`).** Симметричный уже
существовавшему `anchor:`: вместо «якорь рядом — сигнал» требует «диcквалифи-
цирующего слова НЕТ рядом». Список для паспорта (`entity_types.yaml:133`):
качества/изделия/объекта/сделки/транспортного средства/самоходной техники/
технический (единственный, что ПЕРЕД якорем)/груза/товара/оборудования/
безопасности/помещения/проекта/здания/сооружения. Результат: «паспорт
качества» **было 138/138 → стало 0/138** масок типа `PASSPORT` на корпусе v2;
настоящие паспорта не задеты (29/30 на целевом документе, без изменений;
«паспорт гражданина РФ» отдельно проверен — детектируется). Честная оговорка:
часть отсечённых образцов всё равно получает маску — не `PASSPORT`, а
`PHONE`, через ДРУГОЙ, пред-существующий механизм сборки цифрогрупп
(`src/multispan.py`, Stage-E-A) — направление по-прежнему безопасное.

**Найденный при измерении компромисс (не регрессия).** Типизированные
негативы СНИЛС/даты рождения в корпусе v2 (зазор внутри нового допуска,
25/32 символа) ловятся 138 из 138 каждый — расширенный гэп не отличает «то
самое число» от «случайно похожего числа в том же предложении». Направление
безопасное. Заведено в `A2-SNILS-BIRTHDATE-GAP-PRECISION`.

**Эталон.** `tests/corpus_v2/data.py`: `snils_parts`/`snils_value`,
`birthdate_parts`/`birthdate_value`, `deptcode_parts`/`deptcode_value` по
