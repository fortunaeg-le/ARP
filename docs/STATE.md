## 2. Что принесло слияние блока 4

**DEBT-1 — скорость и слепые пятна измерителя.** Ремонтный проход больше не
считает адрес (`skip_address`: `layout_repair` адресные сущности всё равно
отбрасывает — это был мёртвый счёт), плюс кеш разобранного текста в
`_addr_parse`. Профиль назвал стоимость по механизмам: yargy-разбор адреса —
87 % времени детекции, стоимость линейна по числу отданных парсеру символов.
Состав форменной таблицы измерителя v2 больше не константа `T2_TYPES`, а
вычисляется из собранного конфига (`measure_v2.measured_types`: фабричные типы
с блоком `measure:` ∩ разметка v2, минус типизированные негативы) — таблица
3 → 18 типов, вернулись пять типов, заведённых фабрикой после T2.

**MARKUP-V2 — номер договора на корпусе v2.** Записи `DOCNUM` (387 вхождений,
138 документов) переклассифицированы из типизированных негативов в эталонные
сущности. Имя в разметке осталось `DOCNUM` — это имя реестра осей, кодовый тип
детектора `CONTRACT_NO`, пара живёт в `measure_v2._GOLD_ALIAS` рядом с
`MONEY`/`SUM`. `TYPED_NEGATIVES` теперь `("DATE",)`. Исключение по v1
(`V1-SCOPE-CONTRACTNO`) НЕ снималось: v1 заморожен со старым определением.

**TYPES-2 — три типа одним файлом-описанием каждый.** `PASSPORT_ISSUER`
(орган выдачи паспорта), `REGISTRY_NAME` (регистрирующий орган),
`CONTRACT_KIND` (вид договора). У всех трёх `provenance` честный: «из практики
оформления договоров, живым документом не подтверждено». Четвёртый кандидат
`TAX_KIND` отклонён переписью и решением владельца.
