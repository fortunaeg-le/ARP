### Часть 4. Пересъёмка точки отсчёта быстрого набора

**Шаг 1 — доказано.** Три расхождения быстрого набора против замороженной
`results_iter_baseline.json` были: `(д) over-mask прозы[PERCENT] 0 → 110`,
`[TERM] 0 → 34`, `[всего] 34 → 178`. Доказательство — опыт, а не рассуждение:
тот же срез прогнан на ВРЕМЕННОЙ копии `entity_types.yaml`, где `PERCENT` и
`TERM` выключены (`enabled: false`); репозиторий не трогался, подменялся только
путь конфига внутри процесса замера. Результат:

```
ADDRESS   2 ->   2      FP на негативах: 3 -> 3
ORG      32 ->  32      расхождений по линии «д»: 0
ВСЕГО    34 ->  34
```

С выключенными типами этапа T2 линия «д» возвращается в точку отсчёта
БАЙТ-В-БАЙТ, по каждому типу и по агрегату. Третье расхождение — арифметическое
следствие первых двух: 110 + 34 = 144, 34 + 144 = 178. Значит все три — T2 и
ничто иное.

**Шаг 2 — развилка пройдена, но с оговоркой, и она названа.** Тот же опыт
показал, что кроме трёх «регрессов» срез имел ещё пять расхождений в СТОРОНУ

masking B 90,94 → 91,03 %), и они T2 НЕ объясняются — переживают выключение

```

```

Ровно та единственная маска, которую этап T-ARB назвал единственным изменением
