## 1. Файл-описание: формат

Один файл = один тип: `tests/corpus_v2/typedefs/<TYPE>.yaml`. Расположение —
внутри зоны корпуса v2 **намеренно**: стена «`src/` сюда не смотрит» уже
объявлена (`src/CLAUDE.md`), фабрика делает её механической (§5).

Схема (все секции обязательны, кроме помеченных; чего не хватает — роняет
сборку, §4):

```yaml
type: REG_NUMBER                # имя типа = имя в разметке v2 (правило T2: без алиасов)
title: Реестровый номер         # для отчёта U4 и экрана «Что маскировать»
status: active                  # active | corpus_only (эталон есть, детектора нет)

detect:                         # ЕДИНСТВЕННОЕ, что попадает в собранный entity_types.yaml
  form:                         # класс формы (§2) + параметры, ИЗ КОТОРЫХ собирается паттерн
    class: formula_number
    params: {...}
  token_prefix: REGNUM
  anchor: null                  # или regex-строка; null = форма самодостаточна
  anti_anchor: null             # + anti_anchor_window при необходимости
  arbitration:
    mechanism: regex            # regex | ner
    rank: 460                   # место в порядке приоритета; целые с зазорами (§3)
  sets: [personal_requisites, with_money]   # «Максимум» — сентинел, не перечисляется
  measure:
    leak_class: numeric         # numeric | text — какой веткой leak_v2 меряется
                                # (обязателен: молчаливое выпадение = прецедент BIRTHDATE)

generator:                      # видят ТОЛЬКО generate.py, валидатор и тесты-стражи.
                                # В детекторный артефакт не попадает ПО ПОСТРОЕНИЮ (§5)
  provenance: "черновик 2 владельца, поз. В1(б)4; формулировки из живых договоров"
  examples: [...]               # >=5 значений для генератора
  axes: {...}                   # оси форм (модель values.py этапа V2-B)
  negatives:                    # >=3 РАЗНЫХ вида случая, поле kind (урок NEG:
    - kind: ...                 #   один вид = одна дыра, повторённая 138 раз)
      text: "..."
      why: "..."
```

Из одного файла собираются: запись в `entity_types.yaml` (место 1), строка
порядка арбитража (2), состав наборов (3), реестр форм генератора (4-5),
негативы (5), ветка метрики (6) и авто-тесты «каждый example маскируется своим
типом, каждый negative — нет» (7, порождаются параметризацией по typedefs).

### Пример 1 — реестровый номер (класс К1, формульный номер)

```yaml
type: REG_NUMBER
title: Реестровый номер
status: active
detect:
  form:
    class: formula_number
    params:            # эскиз; точные параметры — сессия 2
      groups_min: 4    # >=4 групп — отсекает «№ 118/2024-А» (CONTRACT_NO, у него <=2 разделителя)
      seps: "/-"       # смешение / и -
      letter_group: required   # обязательная буквенная группа («-н»)
      len_min: 15      # разводит с датами и пунктами (ENTITY_SPEC §3.3)
  token_prefix: REGNUM
  anchor: null
  anti_anchor: null
  arbitration: {mechanism: regex, rank: 460}   # ниже PHONE, выше SUM: формульный
                                               # номер специфичнее суммы, вложенная
                                               # дата проигрывает ему по длине (rule 2)
  sets: [personal_requisites, with_money]
  measure: {leak_class: numeric}
generator:
  provenance: "черновик 2, В1(б)4; форма нотариального реестрового номера"
  examples:
    - "77/714-н/77-2024-1-502"
    - "50/121-н/50-2023-4-88"
    # ... >=5, все — облики из живых документов
  axes:
    separators: [slash_dash, dash_only]
    year_position: [middle, tail]
  negatives:
    - kind: cadastral
      text: "кадастровый номер 77:01:0004012:2211"
      why: "чужая номенклатура: двоеточия, нет буквенной группы"
    - kind: gost-ref
      text: "ГОСТ Р 52044-2003"
      why: "ссылка на стандарт — не реестровый номер стороны"
    - kind: clause-chain
      text: "пп. 4/5-1 и 7/2-3 Правил"
      why: "короткие цепочки пунктов: меньше 4 групп, короче 15 знаков"
```

```yaml
  examples:
    - "1-й транш"
    - "транш «Со-единения»"
    - "второй транш предоставляется после..."
  axes:
    form: [ordinal_digit, ordinal_word, named_quoted]
  negatives:
    - kind: generic-plural
      text: "график выдачи траншей"
      why: "родовое упоминание без порядкового номера и имени — маскировать нечего"
    - kind: verb-context
      text: "транширование задолженности"
      why: "однокоренное слово — не транш"
    - kind: foreign-name
      text: "программа «Со-единение» благотворительного фонда"
      why: "имя в кавычках без слова «транш» — чужая сущность (ORG/название)"
```

### Пример 3 — доля голосов (класс К4, слово закрытого списка при числе)

```yaml
type: SHARE_PCT
title: Доля голосов / доля участия
status: active
detect:
  form:
    class: number_with_closed_word
    params:
      unit: '%|процент\w*'                    # тот же закрытый класс, что у PERCENT
      tail: 'голос\w*|уставн\w+\s+капитал\w*' # основание — часть значения (правило v2)
      tail_required: true    # БЕЗ основания это обычный PERCENT — иначе два типа
                             # спорят за каждый «18%»
  token_prefix: SHARE
  anchor: null
  anti_anchor: null          # технические доли уже отсечены anti_anchor у PERCENT;
                             # здесь tail_required сам отсекает их сильнее
  arbitration: {mechanism: regex, rank: 545}  # выше PERCENT: «75 % голосов» длиннее
                                              # вложенного «75 %», но при равной длине
                                              # прав более специфичный тип
  sets: [with_money]
  measure: {leak_class: text}   # значение содержит слова — цифровой run его не ловит
generator:
  provenance: "черновик 2, В1(в)2 + В1(г)1"
  examples:
    - "75 % голосов"
    - "доля в размере 40 % уставного капитала"
    - "25,5 % голосов от общего числа"
  axes:
    unit_spelling: [sign, word]
    base: [votes, capital]
  negatives:
    - kind: bare-percent
      text: "неустойка 0,1 % за каждый день"
      why: "процент без основания голосов/капитала — это PERCENT, не доля"
    - kind: quorum-no-number
      text: "большинством голосов присутствующих"
      why: "нет числа — маскировать нечего"
    - kind: fraction-words
      text: "большинством в две трети голосов"
      why: "дробно-словесная форма — СЕМ, правилами не берётся (ENTITY_SPEC §3.5);
            честный негатив, а не молчаливый пропуск"
```

⚠ Честная оговорка к SHARE_PCT: «число + %» сегодня уже берёт `PERCENT` (этап T2),
то есть заведение SHARE_PCT — это **выделение подкласса из работающего типа**, и
мерить его надо с оглядкой на MASK-SHIFT (маска та же, тип другой).

## 2. Классы форм

Выведены из устройства 18 существующих маскируемых типов (`entity_types.yaml`)
и шести новых из черновика. Класс — это шаблон паттерна + фиксированный набор
параметров; сборка по классу даёт **строку паттерна**, которая и попадает в
собранный конфиг.

| класс | суть | параметры |
|---|---|---|
| **К1 формульный номер** | форма сама себя удостоверяет, якорь не обязателен | группы, разделители, обязательные элементы, длина |
| **К2 число под якорем** | значение — цифры фикс. длины, право на маску даёт якорь (шлагбаум) | длина, якорь, окно, span_group, анти-якорь |
| **К3 число с якорем и КС** | К2 + контрольная сумма (сигнал под якорем, фильтр без — инвариант этапа 4) | + имя валидатора из закрытого реестра `validators.py` |
| **К4 слово закрытого списка при числе** | число + слово-единица закрытого грамматического класса | класс единиц, хвост-основание, границы |
| **К5 составная конструкция** | 2+ альтернативных ветви (каждая — кусок К1/К2/К4) + необязательные хвосты | ветви, хвосты, запреты внутри хвоста (цифры!) |
| **сырой паттерн** | не ложится ни в один класс: паттерн приводится в файле дословно | pattern verbatim + причина, почему без класса |

«Сырой паттерн» — полноправный житель фабрики: приоритет, наборы, негативы,
метрика и авто-тесты собираются как у всех, вручную остаётся только сама строка
регэкспа. Это же — механизм перевода байт-в-байт (§3).

## 3. План перевода 18 типов — поведение не меняется

**Принцип: равенство доказывается на артефактах, а не на поведении.** Сборка
обязана выдавать не «эквивалентный», а **тот же самый разобранный конфиг**:
глубокое равенство словаря `entity_types` (включая порядок записей — он влияет
на порядок детекции) и посимвольное равенство каждой строки паттерна/якоря.
Тогда каждый шаг проверяется за секунды сравнением, а не 10-минутным гейтом.
Гейт — один раз, последним действием сессии перевода: дамп
`results_gate_current.json` до и после **байт-в-байт** (детерминизм корпуса
измерен — 0 расхождений на 10315).

**Сосуществование схем.** `entity_types.yaml` остаётся единственным файлом,
который читает `src/` — но становится СОБРАННЫМ: сборщик
`tests/corpus_v2/assemble_types.py` склеивает `entity_types.base.yaml`
(замороженная копия сегодняшнего файла, непереведённые типы) + typedefs.
Перевод типа = вырезать его блок из base и завести typedef; собранный конфиг
обязан остаться равным. Пока base не пуст, обе схемы живут вместе; PERSON/ORG/
ADDRESS и отрицательные классы остаются в base навсегда (§6).

Шаги (каждый — отдельный коммит, точечно откатываемый):

| шаг | что | чем проверяется |
|---|---|---|
| 0 | сборщик + валидатор + стражи стены (§5); typedefs пусто, собранный == base == сегодняшний файл | новый тест равенства конфига; pytest |
| 1 | `_REGEX_PRIORITY` читается из собранного конфига (ключ `arbitration_order`, собирается из rank); base несёт сегодняшний порядок явно | тест: собранный порядок == сегодняшний список дословно; `assert_priority_contract` остаётся |
| 2 | наборы `type_policy` читаются из конфига (`sets:` у типов base) | тест: составы PERSONAL/…/WITH_MONEY == сегодняшние кортежи |
| 3 | блок «сырых» и К1: EMAIL, DATE, PHONE, PASSPORT, BIRTHDATE | равенство конфига (для сырых — тривиально: строка та же) |
| 4 | блок К2: KPP, BIK, BANK_ACCOUNT, SNILS | равенство конфига: собранный по классу паттерн ПОСИМВОЛЬНО равен старому. Не собирается посимвольно — тип уходит в «сырой», а не паттерн подгоняется |
| 5 | блок К3: INN, INN_PERSON, OGRN | то же |
| 6 | блок К4/К5: SUM, PERCENT, TERM | то же |
| 7 | финал: base = только PERSON/ORG/ADDRESS + отрицательные классы; ПОЛНЫЙ гейт | pytest целиком; дамп гейта байт-в-байт против дампа до шага 0 |

Во время шагов — `subsample.py` как находка, не приёмка (правило прогонов).
Красный тест не чинится ослаблением: разошёлся собранный паттерн — тип
переводится «сырым», расхождение записывается в FINDINGS.

**Генераторная сторона НЕ переводится для старых типов.** Формы MONEY/PERCENT/
TERM/… уже написаны в `values.py`; перенос обязан был бы воспроизвести корпус v2
байт-в-байт (страж `test_corpus_v2_reproducible`), а любое изменение порядка
обращений к `rnd` его ломает. Риск без выигрыша. Фабричная генераторная секция
обязательна только для НОВЫХ типов; `generate.py` получает один общий блок
«вплести формы зарегистрированных typedefs» и не трогает существующие функции.

## 4. Валидатор — что роняет сборку

Валидатор — часть сборщика; сборщик гоняется pytest-стражем, то есть красная
сборка = красный набор тестов, забыть невозможно. Роняют сборку:

| нарушение | текст ошибки (дословно такого тона) |
|---|---|
| нет `generator.negatives` или все негативы одного `kind` | «REG_NUMBER: негативов нет (или все — один вид случая). Тип без негативов не охраняется от переусердствования: один вид = одна дыра, повторённая 138 раз (урок NEG). Добавьте >=3 разных kind.» |

## 5. Стена — механически, а не соглашением

Опасность названа в задании точно: один файл несёт и то, что нужно детектору
(паттерн), и то, что детектору видеть нельзя (примеры значений — по ним
генератор пишет и текст, и эталон). Сегодня стена держится дисциплиной — долг
`V2-WALL-NOGUARD` открыт. Фабрика закрывает его четырьмя механизмами:

1. **Детектор читает только собранный `entity_types.yaml`**, в котором
   generator-секции нет ПО ПОСТРОЕНИЮ: сборщик переносит ключи по **белому
   списку** detect-полей (не вычёркивает лишнее, а переносит разрешённое —
   новый generator-ключ не просочится по забывчивости). `src/` о фабрике не
   знает вовсе: путь и формат конфига для него не меняются.
2. **Самопроверка сборки:** каждая строка из `examples` и `negatives[].text`
   ищется подстрокой в собранном артефакте; найдена — сборка падает (текст
   ошибки в §4).
3. **Импорт-страж (новый pytest-тест, дешёвый, без прогона корпуса):** AST-скан
   `src/**.py` — ни импортов, ни `open()`-литералов, указывающих в
   `tests/corpus_v2/` (typedefs, values, generate, gold_v2) и в `tests/corpus/gold.json`.
   Это закрывает `V2-WALL-NOGUARD` целиком, не только для typedefs.
4. **Размещение:** typedefs лежат в `tests/corpus_v2/` — внутри зоны, куда
   стена уже запрещает смотреть; страж п. 3 делает запрет исполняемым.

Плюс запрет 6 получает автостража: валидатор роняет сборку на detect-секции у
TRANCHE (§4), а тест-страж проверяет, что TRANCHE отсутствует и в собранном
конфиге с token_prefix, и в порядке арбитража — закрывается `V2-TRANCHE-NOGUARD`.

**Честная оговорка, без которой стена — враньё.** Механика защищает от КОДА,
читающего ответы. От ЧЕЛОВЕКА, который пишет паттерн, глядя на свои же примеры
в том же файле, не защищает ничто — и это не новая дыра фабрики: сегодня тот же
человек пишет `entity_types.yaml` и values.py в одной сессии. Следствие прежнее
(красная линия README v2): **цифры на порождённом корпусе — верхняя граница, а
не измерение**; настоящая проверка — реальные договоры. Поле `provenance`
(«откуда примеры») делает происхождение проверяемым владельцем, но не машиной.

## 6. Границы — чего фабрика НЕ делает

1. **Нейросетевой/якорный слой: PERSON, ORG, ADDRESS.** Их «конфиг» — код
   (`anchor_registry.py`, 3 подмеханизма C′, барьеры, проход 2 по леммам).
   Описать это YAML-файлом нельзя, не переписав движок. Остаются в base навсегда.
2. **Отрицательные классы (CLAUSE_REF, ROLE_TERM, COLLECTIVE).** Их суть —
   барьер в арбитраже и переиспользование кода anchor_registry; token_prefix у
   них отсутствует принципиально. Валидатор фабрики про «нет token_prefix»
   ронял бы их по ошибке — они живут в base, вне фабрики.
3. **Арбитражные исключения и механизмы.** Правила `_winner` (длина раньше
   приоритета), граничные окна B3, мультиспан-сборщики, нормализация,
   `_trim_to_free` — код. Фабрика задаёт только МЕСТО типа в списке приоритета,
   не правила игры.
4. **Решения владельца.** В какой набор входит тип, маскировать ли порядковый
   транш, снимать ли запрет 6 — файл ЗАПИСЫВАЕТ решение, не принимает его.
   Человеческие тексты (PROFILE_HINTS, тексты экрана) — руками, как и сейчас.
5. **Корпус v1 и его гейт.** Новый тип в v1-эталоне не появится (заморожен);
   рост линии «д» на новом типе — известный MASK-SHIFT, принимается только
   через `promote_baseline.py` владельцем. Фабрика этого не обходит и не прячет.
6. **СЕМ-типы черновика** (CONDITION, DECISION, PAYMENT_PART, ABBR_CTX,
   дробно-словесные доли): правилами не делаются, файлом-описанием — тем более.

## 7. Цена типа после фабрики

Сегодня: ~полсессии (2,5-3 ч по хронометрам T2/T-GOLD-A: семь мест, каждое со
своим прогоном, плюс поиск забытого места).

После фабрики, по шагам:

| шаг | минут |
|---|---:|
| написать typedef (примеры и негативы — ручная, несжимаемая часть) | 15-20 |
| сборка + валидатор | <1 |
| перегенерация корпуса v2 + `validate.py` + `make_manifest.py` | ~3 |
| авто-тесты из examples/negatives | 0 (порождаются) |
| быстрый набор `subsample.py` + тесты зоны | ~5 |
| **итого до полного pytest** | **~25-30** |

Полный pytest (~8 мин фоном) и единственный гейт в конце сессии — как сегодня,
в цену типа не входят. **Оценка: 30 минут на тип** против ~180 сегодня.
Проверка — сессия 2, хронометром на живом типе (первый кандидат — REG_NUMBER:
класс простой, конфликты разобраны в ENTITY_SPEC §3.3).
