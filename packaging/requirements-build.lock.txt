# ТОЧНЫЕ версии окружения, из которого собран exe (этап U1b, пересборка).
# Не диапазоны: численное окружение (numpy) и версии моделей (natasha/navec/
# slovnet/pymorphy2) влияют на РЕЗУЛЬТАТ детекции, поэтому у клиента должно
# работать ровно то, что мы проверили, а не «совместимое».
#
# requirements.txt — это верхнеуровневые зависимости для разработки (там часть
# пакетов без пинов). ЭТОТ файл — слепок фактической сборки, включая
# транзитивные пакеты, и он проверяется НА СБОРКЕ: packaging/shifrator.spec
# сверяет установленные версии критичных пакетов с этим файлом и роняет сборку
# при расхождении (см. _assert_pinned_environment в спеке).
#
# Воспроизвести окружение:
#   python -m venv venv
#   venv\Scripts\python.exe -m pip install -r packaging/requirements-build.lock.txt
#   venv\Scripts\python.exe -m pip install -e . --no-build-isolation
#   venv\Scripts\pyinstaller.exe packaging\shifrator.spec --distpath dist --workpath build
#
# Третья строка (editable-установка) обязательна, чтобы запустить набор
# тестов, а не только собрать exe: подпроцессные тесты test_g_regression.py
# импортируют file_detokenizer из произвольного cwd, и без неё они красные
# (см. pyproject.toml, [tool.setuptools]). На сборку exe эта строка не влияет
# и в поставку не попадает.
#
# pytest-xdist и wheel ниже — тоже не для exe (детекцию не меняют, в
# _PINNED_CRITICAL спеки их нет): pytest-xdist нужен, потому что pytest.ini
# требует `-n auto`, без плагина набор тестов не стартует вообще; wheel нужен
# редактируемой установке (шаг выше) — без него `pip install -e .
# --no-build-isolation` не собирает editable-обёртку (найдено этапом
# ENV-LOCK, долг ENV-LOCK-INCOMPLETE, docs/STATE.md §8).
