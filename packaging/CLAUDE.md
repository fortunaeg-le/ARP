# Зона сборки

## Круг на собранной программе — обязателен в приёмку этапа

Любой этап, тронувший `src/` или конфигурацию, обязан закончиться кругом на
СОБРАННОЙ программе:

```
venv/Scripts/python.exe packaging/accept_circle.py               # собрать и прогнать
venv/Scripts/python.exe packaging/accept_circle.py --skip-build  # прогнать существующий dist/
```

Круг ходит ДВА пути на изолированном профиле (подменённый `USERPROFILE`,
реальный `~/.shifrator` не трогается) и печатает «ПРОЙДЕН» или «УПАЛ на шаге N»
одной строкой. Плюс реальный документ владельца, если этап трогал детекцию.

1. **HTTP API** (шаги 1–20): сборка + шифрование + восстановление + повторное
   открытие сессии по id — тот же путь, что у командной строки.
2. **ИНТЕРФЕЙС в настоящем браузере** (шаги 21–54, `packaging/ui_circle.py`):
   Edge/Chrome в фоновом режиме по протоколу отладки, без сторонних библиотек.
   Файл кладётся в поле настоящим `File`, значение выделяется настоящим `Range`
   с настоящим `mouseup`; каждый шаг спрашивает, ВИДИТ ЛИ результат человек.

**Почему второго пути мало не бывает (CIRCLE-UI).** Пути №1 хватало ровно до тех
пор, пока не выяснилось, что он пропустил ДВА дефекта подряд: PDF, который
интерфейс не пускал вовсе, и предупреждение о непрочитанной странице PDF,
которого на экране не было НИКОГДА. Оба лежали в ответе сервера, и круг считал
их сделанными. **«Есть в ответе сервера» ≠ «видно человеку».** Проверено живой
пробой: оба дефекта, внесённые обратно, роняют круг на шагах 23 и 50, а шаги
1–20 при этом проходят зелёными. Флаг `--skip-ui` есть только для отладки самого
круга: в приёмку этапа с ним нельзя — непроверенным остаётся весь класс «движок
умеет, интерфейс не пускает». Нет ни Edge, ни Chrome — круг ПАДАЕТ на шаге 21, а
не пропускает молча. Расхождение «движок умеет — экран не пускает» стережёт ещё
и `tests/test_ui_capability_parity.py` (единый источник — `app/capabilities.py`).

**Причина.** `config_cache.default_config_path()` резолвится по-разному в
рабочем дереве и в `sys._MEIPASS` (PyInstaller): дефект этого класса (путь к
`entity_types.yaml` терялся в сборке, фолбэк срабатывал МОЛЧА, фабричные типы
выпадали из арбитража) прожил через полный гейт и 1637 тестов — они все ходят
по рабочему дереву и такой класс не видят по построению (FIX-3,
`docs/JOURNAL.md`). Круг проверен живой пробой: намеренная поломка того же
пути роняет его на шаге шифрования с тем же `ArbitrationContractError`
(ACCEPT-FIX, `docs/JOURNAL.md`).

## Спека

`shifrator.spec` — `--onedir`, не `--onefile` (см. комментарий в файле).
Версии пакетов, влияющих на результат детекции, зафиксированы в
`requirements-build.lock.txt` и ПРОВЕРЯЮТСЯ спекой при сборке — разошлись с
окружением, сборка падает, а не собирает поставку клиенту на непромеренных
версиях. Каждый модуль `src/` и `app/` обязан быть в `hiddenimports`: страж
`_assert_every_local_module_listed` в спеке падает на первом же новом
непокрытом модуле (ленивый импорт внутри функции — класс дефекта STORE/U4:
без него собранный exe тихо теряет функциональность, не падая).
