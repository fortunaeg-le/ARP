# Зона детекции

## Стена: детектор не смотрит в ответы

Работая здесь — `regex_detector.py`, `ner_detector.py`, `anchor_registry.py`,
`syntax_compound.py`, `multispan.py`, `type_policy.py`, `tokenizer.py` —
**не читать и не импортировать**:

- `tests/corpus_v2/values.py` — реестр значений и осей, по которому порождается корпус;
- `tests/corpus_v2/generate.py` — генератор текста и эталона одновременно;
- `tests/corpus_v2/gold_v2.json` — сам эталон;
- `tests/corpus/gold.json` — эталон корпуса v1.

Почему это не формальность: корпус v2 порождён генератором, который писал И
текст, И разметку. Детектор, подсмотревший в этот список, начинает узнавать
ровно те формы, которые генератор умеет порождать, — и замер показывает не
качество детекции, а совпадение двух списков. Цифры после этого не значат
ничего, а понять это по числам будет уже невозможно.

Смотреть в эталон разрешено **измерителю** (`tests/corpus/measure_lib.py`,
`run_measurement.py`, `gate.py`) — это его работа.

Нужен пример конструкции для отладки — брать из документа корпуса
(`tests/corpus/docs/*.txt` читаются свободно) или писать свой синтетический,
но не из реестра значений.

С этапа TYPE-FACTORY-2 стена МЕХАНИЧЕСКАЯ (долг `V2-WALL-NOGUARD` закрыт):
AST-страж `tests/test_type_factory.py::TestWall` роняет набор на любом импорте
или строковом пути из `src/` в зону корпуса; сборщик `assemble_types.py`
переносит в `entity_types.yaml` только белый список detect-ключей и падает,
если значение генератора найдено в артефакте подстрокой.

## Порядок слоёв и приоритеты

Порядок слоёв детекции живёт в ОДНОМ месте — `pipeline.run_detection`. Копий
порядка нет и заводить нельзя: раньше их было три, и интерфейс однажды отстал
на целый этап.

Порядок арбитража с этапа TYPE-FACTORY-2 читается из ключа `arbitration_order`
собранного `entity_types.yaml` (пишет его `assemble_types.py` из rank
файлов-описаний); списки в `tokenizer.py` — умолчание-фолбэк, для дофабричных
типов равны конфигу. Забытый тип по-прежнему роняет сборку
(`assert_priority_contract`). Сам `entity_types.yaml` руками не правится —
он СОБИРАЕТСЯ (см. `docs/HOWTO_NEW_TYPE.md`).

Инварианты, которые нельзя ломать, — [`docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md) §8.
