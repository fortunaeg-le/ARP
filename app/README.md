# SHIFRATOR — десктоп-интерфейс (пилот)

Рабочий локальный интерфейс поверх реального CLI SHIFRATOR: юрист загружает
договор → система прячет персональные данные → **юрист проверяет результат** →
скачивает обезличенный текст → позже восстанавливает точный оригинал.

Всё считается **на этом компьютере**. В сеть не уходит ничего — сервер слушает
только `127.0.0.1`. Это и требование приватности ПДн, и аргумент пилота.

---

## Как запустить

### Для юриста (одним кликом)
Двойной клик по **`app\start.bat`**. Появится окошко «SHIFRATOR запущен» (не
закрывайте его — это и есть работающая программа) и отдельным окном откроется
сам интерфейс. Закончив работу — кнопка «Выход» в окошке статуса (или закрыть
его крестиком); окно интерфейса закроется вместе с программой.

`start.bat` запускает `app/launcher.py` — то же, чем является собранный
конечному пользователю `SHIFRATOR.exe` (см. `packaging/shifrator.spec`,
`docs/archive/reports/HANDOFF_U1_PACKAGING.md`, `README_USER.md` в корне
репозитория). Лаунчер добавляет поверх `app/server.py`: self-check моделей до
старта, файл-замок против зомби-процессов, подбор свободного порта, если
`8765` занят, и **окно приложения** (см. ниже).

### Почему это окно, а не вкладка браузера

Интерфейс открывается режимом `--app=` уже установленного браузера на движке
Chromium (`app/appwindow.py`): окно без адресной строки, без вкладок и без
закладок, со своей иконкой в панели задач. Новых зависимостей это не требует —
Edge есть на любой Windows 10/11 из коробки; порядок поиска Edge → Chrome →
Chromium. Не нашлось ни одного — интерфейс открывается обычным браузером, и
это не ошибка: программа обязана запускаться всегда.

Профиль окна свой (`~/.shifrator/window-profile`), рядом с `launcher.lock`:
окно не наследует расширения и вкладки основного браузера юриста и не мешает
ему работать. Выход из программы закрывает окно — процессы браузера состоят в
объекте задания Windows, поэтому не остаются висеть.

### Из командной строки
```
cd <путь к репозиторию>
venv\Scripts\python.exe app\server.py
```
Затем откройте http://127.0.0.1:8765/ (браузер откроется сам).

Порт по умолчанию `8765`; сменить — переменной окружения `SHIFRATOR_UI_PORT`.

Отдельная установка не нужна: интерфейс использует тот же `venv` и те же
зависимости, что и CLI (`python-docx`, `natasha`, `cryptography`, `PyYAML`).
Своих пакетов не добавляет — построен на стандартной библиотеке Python.

## Три экрана

**1 · Шифрация.** Перетащите `.docx` или `.txt` (или нажмите, чтобы выбрать).
Если документ содержит зоны, которые система пока **не умеет читать** (колонтитулы,
сноски, надписи, вложенные таблицы), интерфейс **явно** это покажет и предложит
осознанный выбор: обработать без них (их текст не будет обезличен и сохранится
локально в `{ID}.unread.json`) или отменить и исправить документ. По умолчанию —
как и CLI — работа **отклоняется**, молчаливой потери текста не происходит.

**2 · Проверка (ядро).** Два текста рядом: исходный и обезличенный, с подсветкой
замен. Наведите курсор на подсветку — увидите тип, исходное значение и метку
(`Иванов Иван Иванович → [PERSON_1]`). Справа — список всех замен, сгруппированный
по типу, со счётчиком «спрятано N значений». Отдельный блок напоминает: система не
гарантирует полноту, проверьте глазами, не осталось ли ПДн. Кнопка «Скачать
обезличенный текст» отдаёт файл `{ID сессии}.txt`. **Сохраните ID сессии** — по нему
восстанавливается оригинал (срок хранения сессии — 24 часа).

**3 · Восстановление.** Введите ID сессии и вставьте обезличенный текст (или
загрузите скачанный `{ID}.txt`). Система вернёт исходные значения на место меток и
покажет точный оригинал; его можно скачать. Ошибки (сессия не найдена / истекла,
пустой ввод) показываются по-человечески.

**5 · Что маскировать** (этап T1-UI). Четыре набора типов списком — название и
одна строка «что прячет» человеческим языком, — под ними все типы галочками для
точечных исключений поверх набора. Экран НЕ считает состав набора сам: и список
наборов, и список типов, и то, какие галочки стоят, приходят с сервера из
`src/type_policy.py` (`core.settings_view`), иначе экран разошёлся бы с
механизмом при появлении нового типа. Сохранение идёт в **тот же**
`~/.shifrator/settings.json`, который читает механизм; второго места хранения
настроек в программе нет. На экране 2 показывается, каким набором получен
результат, и — если набор не полный — что осталось в тексте намеренно.

## Что под капотом

- `app/server.py` — локальный HTTP-сервер (`http.server`), только `127.0.0.1`.
- `app/core.py` — тонкая обёртка: дёргает **реальный** конвейер из `src/` в том же
  порядке, что `shifrator.py::cmd_encrypt` (regex → NER → составные → токенизация →
  сессия), и дополнительно возвращает данные для экрана проверки. Никакой своей
  логики детекции/маскировки — только импорт и вызов.
- `app/index.html` — единственная страница (HTML/CSS/JS, без сборки и внешних
  ресурсов). Раскладка тянется под размер окна: страница целиком не
  прокручивается, прокрутка живёт внутри панелей. Уже `900 px` — вместо
  сжатого экрана честная заглушка «нужен экран пошире»; по высоте содержимое
  ужимается до пола, а ниже пола экран проверки прокручивается, а не режется.
- `app/appwindow.py` — поиск браузера и запуск окна приложения (`--app=`).
- Хранилище сессий — то же, что у CLI: `~/.shifrator/sessions/`. Сессия, созданная
  здесь, восстанавливается и через CLI (`python shifrator.py decrypt <ID>`), и
  наоборот.

Границы: интерфейс — надстройка, `src/` детекции не тронут. Полнота обезличивания —
на уровне самой системы (см. `docs/STATE.md`); интерфейс её честно показывает, а не
приукрашивает.
