# experiments/ — опись живых инструментов

Разбор этапа EXP (2026-08-07): 168 файлов разложены на живые инструменты
(остаются на месте, по каталогу-этапу) и логи прогонов (уехали в
`experiments/archive/<stage>/` через `git mv`, физически ничего не удалено,
кроме случаев с явным обоснованием ниже). Один живой инструмент на строку;
запуск — из корня репозитория, `venv/Scripts/python.exe experiments/...`.

Многие инструменты пишут/читают файлы РЯДОМ С СОБОЙ (`HERE`-путь) — если
входного дампа нет (он уехал в `archive/` или не коммитился), сначала
перезапустите генератор (обычно соседний `run_*.py`/`sweep.py`/`measure_sub.py`),
потом инструмент чтения.

## archive/ — логи и дампы прогонов
Раскладка зеркалит рабочие каталоги (`archive/<stage>/...`), `archive/root/` —
файлы, лежавшие прямо в корне `experiments/`. Ничего не читается кодом «на
лету» — это доказательная база прошлых замеров, а не вход текущих инструментов.

## stage_metric_fix/ — METRIC-FIX (слепота прибора)
- `probe_header.py` — пробой механизма ложного «не найдено» в колонтитулах
- `calib_fragments.py` — ОТВЕРГНУТЫЙ вариант правила (сумма кусков) и замер, почему он не годится
- `calib_chain.py` — принятое правило (куски подряд) и сетка «пол куска x зазор»
- `verify_cases.py` — те же случаи глазами: значение, разорванное переносом, с окрестностью в анонимном тексте
- `probe_profile_leak.py` — почему ФИО внутри имени ИП открыто в наборе по умолчанию
- `narrowness.py` — узость правки прибора сличением дампов, поле за полем
- `recount.py` — пересчёт картины продукта (утечка, класс вёрстки, механизмы)
Дампы и логи этого каталога в историю не идут (`.gitignore` по месту): они
восстанавливаются запуском скриптов на неизменном `src/`. Числа — в записи
журнала METRIC-FIX.
