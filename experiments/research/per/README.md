# experiments/research/per — разведка PER-RECON

Этап РАЗВЕДОЧНЫЙ: `src/` и `entity_types.yaml` не тронуты ни строкой.
Отчёт — [`docs/research/PER-RECON.md`](../../../docs/research/PER-RECON.md).

| файл | что делает | живой? |
|---|---|---|
| `decompose.py` | разбор механизмов с ПРИОРИТЕТОМ (первый подошедший признак) | да, как доказательство ОТВЕРГНУТОГО способа счёта: он завышает подмену символов в 12 раз |
| `multilabel.py` | честный разбор набором меток + сочетания механизмов | да |
| `causal.py` | причинная проба: длиносохраняющее снятие признака и повторная детекция, 324 док. × 5 вариантов, `Pool` с защитой точки входа | да |
| `causal_report.py` | сводка пробы в ЛЮДЯХ, а не вхождениях | да |
| `anchor_probe.py` | словарный разбор значения глазами якоря; деление «словарного потолка» | да |
| `realdoc.py` | профиль механизмов реального договора — ТОЛЬКО счёта, ни строки текста (запрет 7) | да |

`*.txt` рядом — вывод этих скриптов, он же доказательная база отчёта.
`causal.json` и `persons_bad.json` в историю не идут: восстанавливаются
запуском на неизменном `src/`, а весят мегабайты.

Проба `causal.py` знает свой предел и он назван в отчёте (§2): вариант `lb`
правит перевод строки ВНУТРИ сегмента, а настоящий разрыв значения вёрсткой —
это символ сборки PT-1 МЕЖДУ сегментами. Класс вёрстки этой пробой не проверен.
