# CROSSTYPE-RECON — разведка PER (2026-08-19)

Разведка без единой правки продукта. Предмет — **PER-половина долга
`DEFGATE-CROSSTYPE-LATENT`**: эталонное ФИО, у которого на МАКСИМУМЕ нет ни
одной маски своего типа, а территория закрыта маской `ORG` (линия «и» гейта).
Числа сняты с дампа `tests/corpus/results_gate_current.json` (полный гейт после
этапа SEAM-JOIN, 324 док.) и живыми прогонами конвейера.

Вопрос, ради которого этап заведён, поставлен этапом PER-SPREAD дословно:
«Лечение (типизация «ИП + ФИО» как PER) — смена победителя арбитража, решение
владельца, ночью не принималось» (`JOURNAL.md`, 2026-08-18). Разведка обязана
дать этому решению числа: **что это за класс, один ли в нём механизм, чем
сегодня прикрыто и во что обойдётся смена типа.**

## 1. Размер класса и его состав (дамп гейта, 324 док.)

| Единица счёта | Всего | из них PER |
|---|---|---|
| МАСОК чужого типа (`crosstype_mask_pairs`) | 431 | **387 `PER`→`ORG`**, 150 док. |
| ЗНАЧЕНИЙ под чужой маской (линия «и», `single_guard`) | 395 | **361 `PER`**, 143 док. |
| Эталонных вхождений `PER`, не найденных ПО ПРИЧИНЕ ТИПА (`miss_reason`) | — | **386 `wrong_type:ORG`** |

Три числа разные, и разница осмысленна: маска — поштучно (разорванное вёрсткой
значение даёт две), значение — по эталонной сущности, `miss_reason` — по
вхождению замера. Все три об одном классе.

Масштаб для сравнения: эталонных вхождений `PER` в корпусе **3420**, найдено
2758, не найдено 662 — из них **386 (58 % всех промахов `PER`) — это не
промахи детекции, а промахи ТИПА**: человек найден, спан на месте, имя маской
закрыто, но маска называется `ORG`. Остальные 276 — «не найдено ничем».

## 2. Механизм ОДИН, и он назван (`per_recon.py`, живой прогон 143 док.)

Скрипт для каждого из **361** случая класса находит ORG-сущность, накрывшую
человека, и разбирает её происхождение (склейка / кавычки / форма ЮЛ слева /
ключ реестра, выигравший арбитраж типов).

```
МЕХАНИЗМЫ (случаев 361):
  compound_ip_fio     361  док. 143
ЧЕМ ЗАКРЫТО В НАБОРЕ ПО УМОЛЧАНИЮ:
  PER                 361
```

**Механизм ровно один: `syntax_compound.merge_compound_entities` склеивает
«ИП + ФИО» в ОДНУ сущность и называет её `ORG`** (`syntax_compound.py:226`).
Ни одного случая через кавычки, через name-run от формы юрлица или через
арбитраж ключа реестра в классе НЕТ. То есть класс не россыпь мелких дефектов
типизации, а один шов, и решение по нему — одно.

Формы ORG-стороны внутри класса: «ИП» аббревиатурой и «Индивидуальный
предприниматель» прописью. Перенос строки внутри спана склейки — 22 случая, и
они делятся надвое: у 9 разрыв идёт внутри самого ФИО (штатная работа ремонта
вёрстки), а у **13 (13 документов) спан склейки идёт НАЗАД**: начинается с ФИО
одной строки и кончается словами «Индивидуальный предприниматель» СЛЕДУЮЩЕЙ
записи того же человека («`Морозова Екатерина Олеговна\nИндивидуальный
предприниматель`»). Человек в маске, но форма приклеена от чужой строки.

## 3. Сегодня это НЕ утечка — во всех четырёх наборах (живая проба)

`agency_0002`, эталон `[259:279] = 'Беляев Олег Олегович'`:

| набор | что накрывает имя |
|---|---|
| МАКСИМУМ | `ORG` «ИП Беляев Олег Олегович» |
| personal (по умолчанию) | **`PER` «Беляев Олег Олегович»** — возврат из `Entity.shadowed` |
| personal_requisites | `ORG` |
| with_money | `ORG` |

Класс целиком: у всех 361 значения `uncovered_default = 0`, и закрыты они в
наборе по умолчанию именно маской `PER` (столбец выше). Механизм возврата —
`tokenizer._recover_shadowed`, заведён этапом DEFAULT-GATE решением владельца
(закрытый долг `MFIX-PROFILE-IP-PER`).

**Что это значит для пользователя:** утечки нет ни в одном наборе, но **в трёх
наборах из четырёх имя человека стоит под токеном `[ORG_n]`** — то есть юрист
видит в тексте организацию там, где на самом деле человек.

## 4. Что ещё держится на этой склейке (`compound_census.py`, все 324 док.)

Перепись ВСЕХ составных сущностей корпуса — не только попавших в класс:

```
ВСЕГО составных сущностей: 401 в 161 док. (ORG-сущностей всего 1189)
ФОРМА ORG-СТОРОНЫ:   ип_прописью 258 | ип_аббревиатура 130 | иное 13
ТИП СОСТАВНОЙ:       ORG 401
ЭТАЛОН ПОД СПАНОМ:   PER 387 | НИЧЕГО 14
```

**Под спанами склейки на всём корпусе v1 лежит ТОЛЬКО эталон `PER` — ни одной
эталонной `ORG`.** Ни одного случая «склейка накрыла настоящую организацию» в
корпусе нет: 387 спанов накрывают ровно по одной эталонной `PER`, 14 — ничего
(это «ИП Макаров Ю. Н.», «ИП Мельник Д. Ю.» и т. п. в подписных строках, где
разметка v1 человека не размечает вовсе — известная цена этапа PER-SPREAD,
маски на неразмеченной прозе).

Иначе говоря: **склейка сегодня не защищает ни одной организации. Весь её
выход — маски `ORG` поверх людей.**

## 5. Цена гипотезы «составная = PERSON», замеренная на всём корпусе v1

`price_probe.py` — монкипатч ТОЛЬКО в скрипте: составная сущность (та, у
которой непусто `shadowed`, то есть рождённая склейкой) получает тип `PERSON`
вместо `ORG`. Склейка остаётся склейкой: один токен на «ИП + ФИО», границы
спана не трогаются. Прогон полного корпуса (324 док., 199 с), оценка —
штатным `gate.py --results`, оба отчёта рядом: `gate_before.log` /
`gate_after.log`.

**Что становится лучше:**

| Строка гейта | сейчас | с гипотезой |
|---|---|---|
| полнота `PER` | 80.6 % | **91.9 %** |
| полнота TOTAL (BIK-excl) | 91.7 % | **95.0 %** |
| masking C (тип маски == тип эталона) | 96.32 % ↓ | **99.54 %** ↑ |
| масок неверного типа (линия «и») | 431 | **44** |
| значений под одиночной защитой | 395 (`PER` 361) | **34 (`PER` 0)** |
| cross-type в домене masking C | 443 | **56** |
| эталонных сущностей с маской СВОЕГО типа | 11 067 | **11 453** |
| эталонных сущностей БЕЗ маски своего типа | 966 | **580** |
| `PER`, не найденных по причине типа (`wrong_type:ORG`) | 386 | **0** |

masking A (обратимость) — **100.00 % и там, и там**: тип маски восстановление
не трогает, канон у составной не заполнен, подставляется `original_text`.

**Что становится хуже — три строки, все названы числом:**

1. **Утечка: +1 сущность** (`PER` 574 → 575, TOTAL BIK-excl 924 → 925).
   Поимённо: **4 значения ухудшились, 3 улучшились**, и все семь — в трёх
   документах с мутацией разрыва строки. Механизм ухудшения вскрыт прогоном
   (`agency_0010__m2718_linebreak`): пока составная была `ORG`, пересечение
   «составная × залеченный вёрсткой `PER`» решалось арбитражем РАЗНЫХ типов и
   `PER`-маска ложилась целиком (`'Морозо\nва Екатерина Олеговна'`); когда оба
   участника стали `PERSON`, пересечение решается внутри ОДНОГО типа, и маска
   обрезается до `'Морозо'` — хвост остаётся открытым. Это правка в
   `_resolve_overlaps`, а не довод против гипотезы, но чинить её обязан тот же
   этап, который меняет тип.

2. **Линия «д» (порча прозы): `PER` 4 → 18, `ORG` 351 → 337. Агрегат 2906 →
   2906 — БЕЗ ДВИЖЕНИЯ.** Ни одного нового символа прозы под маской не
   появилось: те же 14 масок («ИП Мельник Д. Ю.», «ИП Ершова И. А.» и др. —
   подписные строки, которые разметка v1 не размечает вовсе) просто сменили
   имя типа. Гейт при этом покраснеет: допуск на линии «д» — +0 ПО КАЖДОМУ
   типу, а не только по агрегату.

3. **Линия «е» (границы): перебор `PER` 17 → 398 сущностей, 172 → 8695
   символов.** Разобрано поимённо: **373 сущности / 8328 символов из этого
   прироста — те самые 386 значений класса, которые ВПЕРВЫЕ попали в замер
   границ** (пока маска называлась `ORG`, эталон `PER` в линию «е» не входил
   вовсе: у него не было маски своего типа). Лишние символы — это ровно
   «ИП » и «Индивидуальный предприниматель » внутри маски. Остальной `PER`
   прибавил 8 сущностей / 195 символов перебора и 1 сущность / 22 символа
   недобора — это тот же документ из п. 1.

   То есть перебор здесь — не порча документа (агрегат линии «д» не
   шелохнулся), а **следствие того, что маска шире эталона на юридическую
   форму**. Вопрос владельцу ровно один: «ИП» — часть персональных данных
   человека или нет.

## 5а. Та же гипотеза на корпусе v2 (138 док., `price_probe_v2.py`)

Свежего дампа v2 в репозитории нет, поэтому прогона два — БЕЗ патча и С ним
(`v2_before.log` / `v2_after.log`, отчёты штатным `measure_v2.py --results`):

| строка v2 | без патча | с патчем |
|---|---|---|
| masking A (обратимость) | 100.00 % | 100.00 % |
| masking B (границы) | 95.19 % | 95.19 % |
| **masking C (тип маски)** | 94.01 % | **96.07 %** |
| cross-масок ВСЕГО | 482 | **316** |
| из них `ORG` | 167 | **1** |
| маски «ни на что» (порча), агрегат | 845 | **845 — без движения** |
| та же порча по типам | `ORG` 152 | `ORG` 144 + `PER` 8 (переатрибуция) |

Направление то же, что на v1, и ни одна строка v2 не ухудшилась. Полноту `PER`
корпус v2 не меряет вовсе: в его форменной таблице 22 фабричных типа, `PER`
среди них нет — поэтому главный выигрыш v1 (полнота 80.6 → 91.9 %) на v2
проверить нечем, а вот тип маски и порча документа проверяются, и обе строки
либо лучше, либо без движения.

## 6. Три варианта решения — и что каждый стоит

| Вариант | Что делает | Плюс | Минус |
|---|---|---|---|
| **A. Составная = `PERSON`** (замерено выше) | тип склейки меняется, границы нет | полнота `PER` +11.3 пп, masking C +3.2 пп, класс `PER`→`ORG` исчезает целиком | перебор границ +8.3 тыс. символов (форма «ИП» внутри маски), линия «д» краснеет переатрибуцией 14 масок, +1 утечка до правки `_resolve_overlaps` |
| **B. Не склеивать, когда ORG-сторона — только форма «ИП»** | «ИП» остаётся открытым словом, ФИО получает свою `PER`-маску | границы точные, перебора нет | теряется смысловая целостность стороны договора (два токена вместо одного); слово «ИП» в тексте для LLM само по себе не ПДн |
| **C. Оставить как есть** | — | ноль работы, ноль риска | 386 вхождений `PER` считаются ненайденными, три набора из четырёх показывают человека под `[ORG_n]`, долг живёт |

Варианты A и B отличаются ровно ответом на вопрос «входит ли «ИП» в маску
человека». Замерен вариант A (он ближе к нынешнему поведению: один токен на
сторону договора); вариант B этой разведкой НЕ мерен.

## 7. Чего разведка НЕ делала

* **Ни одной правки в `src/`** — весь замер сделан монкипатчем внутри скриптов
  `experiments/crosstype_recon/`.
* **Решение не принималось.** Смена победителя типа — решение владельца
  (`JOURNAL.md`, PER-SPREAD, 2026-08-18).
* **Реальный документ не гонялся** (его нет на машине, запрет 7). Класс на нём
  не мерен ни разу; синтетический корпус v1 «ИП + ФИО» содержит в 161 документе
  из 324, и это доля КОРПУСА, а не живых договоров.
