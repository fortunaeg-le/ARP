# Приборы этапа DOG (2026-08-05)

Измерение реального договора владельца. **Ни один скрипт не печатает
содержимое документа** — только числа, координаты, типы и отпечатки sha256.
Путь к документу задаётся СНАРУЖИ (переменная окружения `ARP_REAL_DOC` и/или
первый аргумент командной строки, где применимо) и указывает ВНЕ репозитория;
сам документ в репозиторий не попадает, значение по умолчанию не предусмотрено.

| Файл | Что меряет |
|---|---|
| `coverage.py` | Часть 1: какую долю документа программа не читает. Классифицирует КАЖДЫЙ узел `w:t`, воспроизводя правило чтения `extractor` (а не доверяя ему), и считает символы по причине непрочтения |
| `determinism.py` | Часть 3: недетерминизм послойно (L1 сегменты → L2 вход нейросети → L3 её выход → L4 адрес → L5 арбитраж → L6 анонимный текст). Режимы: `inproc N`, `one`, `collect <файл>`. Вход и выход нейросети снимаются обёрткой над `ner_detector.Doc` |
| `part4.py` | Часть 4: разбор пропусков по классам + два названных подозрения (ИНН физлица под переносом, адрес под переносом) |
| `leakcheck3.py` | Приёмка (а): доказательство, что содержимого документа нет в рабочем дереве и в диффах сессии. Иглы — 5-граммы и длинные числа САМОГО документа |

**Урок про иглы** (первая версия проверки была негодной и дала 926 ложных
файлов): «редкое в документе длинное слово» — плохая игла, потому что
«ответственности»/«обязательства» редки внутри договора, но обычны в любом
русском тексте. Годятся только словесные 5-граммы и длинные цифровые прогоны.
Совпадение 1-из-600 — подпись общего юридического шаблона, а не дампа;
проверять его следует сверкой с заведомо синтетическим корпусом v1.

Разбор и цифры — [`docs/JOURNAL.md`](../../docs/JOURNAL.md), запись DOG.
